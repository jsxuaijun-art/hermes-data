# 品牌 / 实体全网提及审计（Brand Mention Audit）

配套 `scraping-request-handling` 的「实体/品牌全网提及审计」需求类型。
2026-10-13 首例：徐总「搜索全网，列出所有提及'苏州盈信'的网站或短视频平台等社交媒体，尤其是有负面评价的」。
配套纪律：引用/摘录类内容同时受 `content-evidence-discipline`（先核原文、给可点链接、不得推断性补写）约束。

---

## 1. 交付契约

**交付物 = 分类清单 + 结论建议，不是过程叙述**（承 `scraping-request-handling` 交互契约）。

Excel（三色标注，一行一条命中）：

| 列 | 内容 |
|---|---|
| 序号 | N1/P1…（N=负面，P=正面/中性） |
| 性质 | 🟥负面 / 🟩正面 / ⬜中性 / 🟨同名混淆 |
| 平台/官网名称 | 站点名 + 所属集团（如"名企在线 71so.cn（企优托同集团）"） |
| 标题或位置 | 文章标题 / 页脚植入 / 列表页 |
| 链接 | **完整可点 URL**，一条不能少 |
| 时间 | 发布日期或"持续在线" |
| 关键内容摘要 | 负面条目**逐句摘录原文**，不转述、不改写 |

Md 说明：三、未命中（可放心）／四、已核查确认"未提及"的同类软文／五、按急迫度的动作建议／末尾数据纪律声明（"所有负面内容均摘录自原文、附可点链接，未做任何推断性补写；无法访问的页面已注明"）。

打包：folder → zipfile → rmtree，桌面只留 `<任务名>.zip`（`content-evidence-discipline` 的打包铁律）。

## 2. 查询矩阵（逐格填满才算查完）

不要只搜品牌词。每个平台单独查一遍 —— **没查过的平台不能写"未命中"**。

| 类 | 站点 | 查询式 |
|---|---|---|
| 通用搜索 | 通用后端 | `"<品牌全称>"`；`"<品牌简称>"` |
| 站内定向 | 任何疑似命中站 | `site:<域名> <品牌>` |
| 企业库 | 天眼查/企查查/爱企查 | `<主体全称> 爱企查`、`百度百科 <主体全称>` |
| 司法/监管 | 裁判文书网、行政处罚公示 | `<主体全称> 行政处罚`、`<主体全称> 司法案件 OR 涉诉` |
| 政府/行业 | 主管局、行业协会、政务网 | `<行业>协会 <品牌>`、`<品牌> 会员 退出`、`<品牌> 公示` |
| 招聘 | BOSS直聘/前程无忧/58/垂直人才网 | `<主体全称> 招聘 BOSS直聘 OR 前程无忧` |
| 社交 | 抖音/小红书/微博/B站/知乎/视频号 | `site:douyin.com <品牌>`、`site:xiaohongshu.com <品牌>` … |
| 点评投诉 | 大众点评/高德/百度地图/黑猫/12315 | `"<品牌>" 大众点评 OR 高德 评价` |
| 竞品软文 | 同业竞品的自家站与兄弟站 | `site:<竞品域名> <品牌>`、`<地区><行业> 评测报告 <品牌>` |

**执行方式**：全部查询丢进一个 `execute_code`，循环调 `web_search(q, limit=12)` 并打印 `title / url / description[:200]`。一次 8–10 条查询约 30 秒；逐条发工具调用要十几轮往返。

## 3. 逐条验证三步（不可省）

1. `web_extract([url], char_limit=25000)` 拉正文。
2. **点名正则校验**：`len(re.findall("<品牌名>", content))` —— 为 0 就丢弃。**摘要命中 ≠ 正文命中**（实测多篇"苏州代账排名"软文正文完全没提目标品牌，只靠搜索摘要会误报为"命中"）。
3. 负面条目摘录原文片段 + 记录 URL + 日期。

## 4. 竞品 AI 黑稿签名（4 条，全中即认定）

同行"XX地区代账/财税公司深度评测报告"这类稿，核这四条：

1. **署名/来源自认 AI** —— 如"来源：AI招财兔数字员工"。
2. **对比对象含作者自有品牌** —— 名单里有排名第一的那个牌子，且它属于发文方（百度百科可查股权/品牌归属）。
3. **"第三方数据"无出处** —— "500份问卷""1200条客户反馈""某白皮书"全不给链接、不可验证。
4. **同一稿件多落点发布** —— 竞品官网 + 同集团兄弟站各发一份（查兄弟站页脚邮箱/备案，如 `kefu@qiyoutuo.com` 即暴露同属一个体系）。双落点会让品牌词的搜索首屏被同一条失实内容占满。

**为什么值得挖**：这类稿件为了显得"实测"，往往写出**可被直接证伪的硬伤事实**（成立年份、注册资本、门店数、许可证编号、员工数）。拿到硬伤 = 澄清文 / 平台投诉"不实信息" / 《反不正当竞争法》第11条商业诋毁函的抓手。

## 5. 覆盖边界怎么写（诚实边界，必写）

交付里必须有一节说明哪些平台**未能穷尽及原因**，否则读者会把"我没查到"误读为"不存在"：

- **百度**：无头浏览器访问会 302 到 `wappass.baidu.com/static/captcha/tuxing_v2.html` 图形验证码 → 这是反爬常态。**改走通用搜索后端 / Bing，或用 `site:` 逐站枚举**，不要卡在百度上反复重试。
- **抖音 / 小红书 / 大众点评 / 黑猫 / 12315**：需登录态 → 用 `site:<域名> 品牌` 枚举 + 通用搜索交叉，抖音/小红书短视频内的口播内容无法覆盖，如实写明。
- **Bing（cn）**：偶尔返回与查询无关的缓存结果 → **重发一次或换后端**即可，不要据此判定"无结果"。
- **企业信息平台**（企查查/天眼查/爱企查）：正文页常需登录，能拿到的是搜索摘要与关联展示位 —— 标题级证据可写，正文详情需注明"仅摘要"。

## 6. 三类必须单列（不能混进普通条目）

- **🟥 政府/行业官网公示** —— 杀伤力最大：客户一搜品牌名就看见，且与公司官网自述经常直接冲突。必须单独提示"立即内部核实"（是欠费？未年检？误会？），并给出异议/补办路径。
- **🟥 冒用 / 搭便车** —— 第三方站在**页脚**反复植入"<品牌>讨债是一家合规模的讨债公司…"这类文案做 SEO，把品牌名与讨债/催收语境绑定，污染搜索结果。非本公司主体，属冒用；对策是向该站及其主机商投诉 + 正向内容顶首页。
- **🟨 同名混淆** —— 名称近似但主体不同的公司（含"<品牌>会计师事务所有限公司"这类近似名，以及查询平台的"相关企业"推荐位），与本公司无股权关系，但稀释品牌辨识度，需单列说明。

## 7. 工作实例（2026-10-13 苏州盈信，供复用参考）

- **需求**：搜索全网（排除本公司官网 yingxinkuaiji.com）所有提及"苏州盈信"的站点/社交平台，负面优先。
- **结果规模**：5 条负面/需处理 + 16 条正面中性；社交平台（小红书/抖音/微博/B站/知乎/视频号）与点评投诉、司法处罚**均未命中本主体**。
- **最严重的一条**：竞品集团官网 + 同集团兄弟站的**双落点 AI 软文**，逐句点名"投诉率 10.2%、复购率 38%、12 家客户被税务约谈、成立 2021 年"——成立年份与工商登记直接矛盾，署名 AI 工具，对比对象为其自有品牌。四条签名全中。
- **第二严重**：地方行业协会官网的**拟清退会员公示**，55 家名单内含该公司，与公司官网自称"成员单位、官方备案可查"口径冲突。
- **交付**：21 行三色 xlsx + md 说明（含未命中清单、竞品在投的同类软文清单、按急迫度的三条动作建议），folder→zip 入桌面。
- **可复用要点**：①先铺平台矩阵再搜品牌词；②`web_search` 批量循环；③命中页正则点名校验；④覆盖边界如实写；⑤政府公示与黑稿硬伤是最有价值的两类产出。
