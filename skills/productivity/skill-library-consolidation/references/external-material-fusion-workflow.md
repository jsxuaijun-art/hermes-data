# 外部素材融合进母skill 的工作流（2026-09 实操）

场景：用户丢来一份外部文档（客户话术 docx/pdf、培训材料、实战案例 + 他自己的应对草稿），
要求「分析并融合进话术 skill」。母skill 已有几十个 reference，融合的难点**不是写字，是落点**。

---

## 第 0 步：先判「有没有新东西」——别做搬运工

通读后**先和母skill 已有弹药做比对**，明确回答：这份材料里真正【新的、之前没有的】是几块？
本次（代理记账服务边界手册）的结论是 3 块新东西：
1. 法规溯源（会计法条 + 代理记账办法条款）——全新法理弹药
2. 规模经济硬数据（月成本、人均户数、单客户月均工时 vs 全职工时）——把「我们亏本」从情绪变数字
3. 交付物料（告知书成稿 + 合同边界条款）——签约时书面化

**已有内容一律不重复落地**。向用户交付这个判断（"新的是这三块"），再动手——用户据此才能
判断融合得对不对。比对结论本身就是价值，别省。

---

## 第 1 步：落点决策——横跨多阶段时怎么放

两种模式，按素材性质二选一（**别默认单独立目录**）：

| 素材性质 | 落法 |
|----------|------|
| 一套**可复用打法**，多阶段都要整套搬用 | 立「通用模块」目录，SKILL.md 专节声明「跨阶段可调用」 |
| 某个**具体异议/场景的具体应对** | 挂**主阶段**，在其它适用阶段加**一行指针**（"报价阶段提前可用"） |

本次实例：
- 「客户想以低价获得高服务」→ 主落 **阶段七**（老客户压价），阶段三报价阶段加一行「提前可用」。
- 「服务边界书面物料（告知书/合同条款）」→ 挂 **阶段二**（签约时书面化）。
- 「法理+成本数据」→ 并进 **00-核心弹药库/core-logic.md**，标注「阶段三/五/七/八通用」。
- 「客户事后追责『没提前提醒我』(久悬户/挂账)」→ 挂 **阶段五**（服务提醒同主题）。

落点建议要**附理由并请用户复核**（用户会明确说"我建议放阶段七，但由你决定"——给出你的推荐
+ 一句理由，再让他一句话就能否掉/挪走）。同时 SKILL.md 的**触发映射表必须补一行**，
否则下次触发不到。

---

## 第 2 步：加，不换——保留用户原话骨架

用户给的实战话术是**他自己的语气**，改写只做加法：
- **保留**他原有的骨架（如：合同义务划分 → 几百块 vs 月薪上万 → 高考老师类比 → 驾照类比 → 应知应会划线）
- **只补强**逻辑薄弱处。本次三处补强：
  1. 补「主权之击」：把争议事项归到书面边界的**非约定服务范围**（久悬户=账户/资金管理，代账从未经手）——
     用户原话没点破这一层，加上后论证才闭环。
  2. **柔化有指责感的类比**：原版高考老师类比近似「老师你没教我」＝暗指客户不讲理，改成
     「知识点是基础，覆盖面一起磨合」。类比要卸责，不能踩客户。
  3. **转档位收口**：当场给价值（查解决方案）→ 拉进提醒清单 → 顺势引导升级档位，而不是把
     深度服务免费承诺出去。母skill 的「不白给」原则必须在融合时落地。

---

## 第 3 步：合并优于散落（用户明确偏好）

用户原话：「都改。把原始 docx 也复制一份进 references 目录留底」。

- **优先并入既有 reference**，不要每来一段素材就新开一个文件。本次 3 个新文件被压成 2 个：
  - 「法规与分析」→ 并进 `00-核心弹药库/core-logic.md`（同一主题，本就该在一起）
  - 「告知书 + 合同条款」→ 作为**附录**并进 `02-首次接触/建群开场白_完整流程.md`（同属签约交付）
- 文件数膨胀是母skill 的敌人：skill 列表的注意力预算 + 未来翻找成本都在涨。
- 合并后**删掉被并入的独立文件**，并把所有指向旧文件的引用重指到新位置。

### 源文档留底

用户问「会不会占用大量容量，如果不占那就留底」——判断标准：**体积小就留底**。
本次原文 docx 41KB，完全可忽略 → 复制到 `references/源文档/<原名>.docx` 留底，
保留原始口径可回溯（日后客户引用原文措辞、或要核对"是不是你改的"时有据）。
体积大（>1MB，如整套 PDF 手册/扫描件）则记录来源与获取方式，不留二进制。

---

## 第 4 步：重指引用 + 吊链校验

合并/删除/改名 reference 后，**必做**：

```bash
cd <skill_dir>
grep -rn "被删文件名1\|被删文件名2" --include=*.md .    # 应为空
python3 scripts/verify_skill_refs.py .                  # scripts/ 在同母skill 内
```

`scripts/verify_skill_refs.py` 会区分「真吊链」和「同级式引用」——母skill 里普遍存在
`references/<裸文件名>.md` 这种实际指向同级子目录文件的写法，**只按全路径解析会全部误报**。
脚本对裸文件名先试同目录、再全树按名搜索，搜不到才算真吊链。

引用重指的具体位置，逐个阶段都要过一遍（本次 4 处）：
阶段二 bullet、阶段三 S3 正文、SKILL.md 触发映射表、以及新文件内部的交叉引用。

---

## 第 5 步：验收并向用户报告

- 无残留旧文件名引用（grep 空）
- 校验脚本 0 吊链
- 新文件行数/字节 + 触发映射表已补行
- 向用户报告时按**「落点 → 补强 → 结构变化 → 留底」**四条列出，并主动提出下一步
  （本次："要我用这个场景套新话术跑一遍成品给你核对版式吗？"）

---

## 坑

- **落点别问"放哪个阶段"就真的干等**：用户说"由你决定、与我商量"= 要你的推荐 + 让他一句话
  可否掉。给推荐并把活干完，比来回确认更符合他的效率偏好（本次两轮都直接干完+邀复核，用户接受）。
- **别把「已有弹药」再落一遍地**，会稀释母skill 的检索质量。
- **触发表漏补**是静默失效：内容写进 reference 但触发映射没这行，下次同类问题根本走不到。
- **类比把控**：卸责类比一旦带指责感，就从"化解"变成"激化"，改写时必须过一遍"这句话读起来像不像在说客户不讲理"。
