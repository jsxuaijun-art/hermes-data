# 落笔前的三道门：型号真实性 / SKU 在售 / 系统兼容

> 2026-10-22 建立。起因：在打印机选型任务中，凭命名规律推出了**不存在的型号
> "奔图 P3016DW"**，写进给客户的交付文档，连错两版、返工两次，并把该型号写进了技能库、
> 污染了多个后续会话。本文件是防止这类返工的可执行清单。
>
> **适用**：任何"给客户推荐具体型号"的任务 —— 办公设备 / 电脑 / 税控设备 / 家电 /
> 软件产品版本 / 云服务套餐。型号名越具体，翻车代价越大。

## 为什么型号推荐比参数推荐更容易翻车

参数（速度、月负荷、耗材结构）可以按品类通性推断，错了还能修；
**型号名是一个可以被客户直接拿去下单的标识符，错了整份文档作废**，
客户还会在商家面前暴露你的不可靠。

三种典型翻车方式：

| 翻车方式 | 本次实例 | 后果 |
|---|---|---|
| **命名规律推演** | 见到 P3016D，按"D=双面 / W=无线"推出 P3016DW | 型号不存在，返工两版 |
| **官网在架当在售** | 官网 P3016D 页留了"立即购买"按钮，链接点开是"商品已下架" | 推荐了生命周期已结束的机型 |
| **规格表当驱动支持** | 规格表列 OS 版本，实际驱动下载页未必放出该系统的驱动 | 客户装机失败 |

## 三道门（顺序不可反，缺一门必返工）

### 门 1：型号真实存在

- **型号名只能从厂商官网 / 电商页照抄，永不推演。**
- 交付文档里出现的**每一个**型号，都必须能在**厂商官网找到同名产品页**。
  只出现在第三方电商标题里的"型号"不可信（那是店铺自己拼的 SKU 名）。
- 自查话术：*"这个型号字符串，是我从哪一页抄下来的？"* 答不上来就说明是推的。

### 门 2：SKU 在售

- 打开厂商官网产品页上那个**「立即购买」按钮指向的链接**，确认不是"商品已下架"。
  厂商官网会**常年保留停售机型的产品页**，页面在架不代表货在卖。
- 平台侧交叉验证：电商搜索该型号，看是否有**明确的在售商品条目**（而非只有配件/耗材）。
  搜不到明确条目 = 国内主销状态存疑，必须在文档里标注"需确认在售"。
- 型号下架意味着**生命周期结束**，不要写进给客户的采购建议书 —— 即使参数最漂亮。
- 若厂商官网链接已失效，优先改用**厂商官方店名单页**（长期有效）替代具体 SKU 链接。

### 门 3：系统兼容（尤其老系统）

- **以厂商「驱动下载」页为准，不以产品页规格表为准。** 规格表常保留老系统字样，
  实际未必放出驱动。
- 重点系统：**Win7 / WinXP / macOS 老版本 / 国产系统（麒麟、统信）**。
  Win7 微软 2020-01 已停止支持，**2023 年后上市的新机型普遍不再提供 Win7 驱动**
  （佳能、惠普、奔图新机一样）—— 老办公环境下这是**硬门槛**，不满足就整机不可用。
- 交付前先问清：客户是否还有老系统机器？必须本机直连打印，还是可走局域网共享？
- 解法优先级：① 网络共享（用客户真实的业务软件任务现场实测）
  ② 选仍提供该系统的驱动、并**要求商家现场装机验证** ③ 建议客户升级老机器。

## 标准操作序列（可直接照做）

1. 从厂商官网产品页抄下**确切型号名**与关键参数。
2. 打开该页「立即购买」链接，确认在售；下架 → 回到候选池重选，或标注"需确认在售"。
3. 去厂商「驱动下载」页，逐型号核对客户所有在用系统的驱动是否提供。
4. 记录**核实日期 + 来源 URL**（写进交付文档与技能库）。
5. **三道门都过了，才允许把型号写进交付文档。**
6. 文档里同时给"采购前必做"的现场验证动作：带客户真实纸样 / 用客户真实业务软件试打、
   用客户那台老系统电脑试装机。

## 报告纪律：发现推荐错了怎么处理

本次做了两轮修正，用户没有不满，反而继续追问 —— 因为处理方式是：

1. **第一时间明说"我错了，错在哪"**，不要模糊成"信息有更新"。
2. **解释错误成因**（我按命名规律推的），让用户知道这是系统性风险还是偶发笔误。
3. **给出已核实的替代项**，不是只道歉。
4. **主动列出需要一并更正的其他产物**（已交付的 zip 里的 docx、技能库里同样的错误）。
5. **不要再急着拍板** —— 连续翻车后，把"需要用户确认的前提"先交还给用户，
   等前提明确再出最终清单。这比再来一版未经核实的推荐更可信。

## 反面教材：不要做的事

- ❌ 按同系列命名规律"补全"型号（A 有、B 应该有）
- ❌ 用"官网有产品页"证明"能买到"
- ❌ 用规格表的 OS 列表证明"驱动支持"
- ❌ 把型号写进交付文档后再去核实（顺序反了就是返工）
- ❌ 同时给多个未核实型号，指望用户自己去分辨哪些能买
- ❌ 把"厂商建议零售价"当作"成交价"写进文档而不标"以询价为准"
