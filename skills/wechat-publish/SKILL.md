## 触发指令

用户说：
- "写一篇关于XXX的公众号文章"
- "写一篇XXX的文章"
- "发一篇XXX"
- **发了视频链接（抖音/YouTube/B站等）→ 进入"视频→文章"分支工作流**

## 总工作流概览

公众号文章有**两条入口**：

| 入口 | 触发方式 | 流程 |
|:-----|:---------|:-----|
| 主题写作 | 用户说"写一篇关于XXX的文章" | 第0步（发散建议）→ 第1步（写作）→ 第2步（配图）→ 第3步（发布） |
| **视频→文章** | 用户发视频链接 | **见下方独立工作流** |

## 工作流（4步 — 含用户确认环节）

### 第0步：确认风格 + 发散建议

发文前先问两件事：

**① 排版风格**：列出当前可用风格编号让用户选，默认01。

**② 发散建议**：用户给主题后，先分析并提出2～5个可选的扩展角度，让用户圈定范围再动笔。格式：

```
💡 发散建议（可选加）
├ A. xxx — 一句话说明价值
├ B. xxx
├ C. xxx（简略）— 标注详略
└ 确认后出稿
```

### 第1步：写文章

1. **分析主题** → 理解文章中心思想、目标读者、写作目的

2. **写摘要（关键步骤）**：frontmatter 的 `abstract` 字段**必须人工编写**，不能留空让微信自动抓取。规则：
   - 字数：**120字以内**
   - 目标：封面下方的卡片预览区，让读者看到就想点开
   - 技法：制造信息差（"你知道XX吗？"）、制造紧迫感（"XX新规来了"）、制造好奇心（"XX到底怎么算？"）
   - 示例：`2026年7月25日，市场监管总局对携程开出51.79亿元反垄断罚单。这不是你刷着玩的热搜——罚款为什么不能税前扣除？你的合同有没有踩红线？一条条说清楚。`（97字，制造好奇心+利益相关感）

3. **文章结构套路**：
   ```
   是什么 → 怎么定 → 多视角解析 → 常见坑 → 实操建议
   ```
   - 当话题对不同读者群体都有价值时，**分割受众**：上半篇给A群体，下半篇给B群体（如"创业新手篇"+"已有公司老板篇"），中间用 `---` + `# 下半篇：xxx篇` 隔开
   - 给**可套用的公式**（如：注册资本 = 行业门槛×1.5）
   - 关键对比用**表格**（`|概念|一句话解释|` 格式，右栏=大白话）
   - 表格第一列表头用「**序号**」，不用「#」
   - **⚠️ 3列及以上表格必须加横向滚动**：手机屏幕宽约375-414px，3列表中文字会溢出截断。3列（含）以上的表格必须用HTML包裹：`<div style="overflow-x: auto; -webkit-overflow-scrolling: touch;"><table>...</table></div>`。2列表格无需此处理，原生渲染即可。
   - 每个坑/要点用**加粗导语**（如"坑一：xxx"），方便扫读
   - 结尾有**总结段落**或"一句话总结"金句
   - ⭐ 已成功参考模板：`references/article-structure-registered-capital-2026-06-30.md`（注册资本主题，含上下篇分割受众结构）
   - ⭐ 热点新闻借势模板：`references/article-structure-hot-news-2026-07-25.md`（反垄断/携程罚单主题，含AB路线融合+开篇狠辣技法+配图搭配）
   - ⭐ 以数治税草稿改稿模板：`references/公众号生产案例-以数治税2026-07-25.md`（用户提供.docx草稿→改稿的生产案例，含改稿策略表、结构定稿、配图教训）

4. **写Markdown** → 含完整 frontmatter：

```yaml
---
title: 文章标题（吸引点击）
author: 苏州盈信财税
cover: /tmp/cover_article.jpg   # 发布前替换为 asset://xxx 或 http://127.0.0.1:8080/images/xxx.jpg
abstract: 120字以内摘要，显示在卡片上
reading_time: X分钟    # 预计阅读时间，根据文章长度估算后填入
---
```

4. **文章要求**：
   - 开头有钩子（黄金三秒）+ 场景切入（让读者觉得"说的就是我"）
   - 结构清晰（小标题分段）
   - 给具体方案/话术/模板/公式，不给抽象概念
   - 引用法规时标注具体条文号，但不堆砌法条
   - 结尾加「苏州盈信企业管理有限公司」品牌落款（**注意：不是「盈信企业管理（苏州）有限公司」**）

### 第2步：配图

**⚠️ 配图铁律（纪律）**：
1. **禁止重复使用**：每篇文章的封面图、正文配图，必须用从未在任何历史文章中用过的图片。每次发文前，检查服务器 `/var/www/html/images/` 里所有现有图片，旧图一律不用。
2. **必须匹配章节中心思想**：每张配图必须精准对应它所在章节的核心内容，不能是"差不多"的通用图。封面图匹配全文主题，正文配图各自匹配所在小节主题。
3. **全量评估机制**：写文章前，先列出需要几张配图、每张图的主题关键词，再逐一搜索对应Unsplash图片。禁止用一张图塞多个章节。
4. **文件名须为新且唯一**：上传时用 `cover_<主题>_<日期>.jpg` 和 `section_<序号>_<主题>.jpg` 格式，避免覆盖旧文件。
5. **先检查后下载**：搜索到一张图后，先在对话中确认"这张图是否曾被使用过"，再下载上传。

6. **图片需要替换时的完整流程（2026-07-25 已验证场景）**：当用户指出某张图用过了/不合适需要全量换图时：
   - 先用 `ls -lt /var/www/html/images/` 查看服务器上的历史配图清单，建立"避用清单"
   - 然后用 `session_search(query="已发文章配图")` 查历史文章用过的 Unsplash photo ID
   - 全部换新的 Unsplash photo ID，不要只替换"重复的那张"——用户会记住两张图一起出现过
   - 同步更新三处：markdown 中的封面路径 + 正文配图路径 + 服务器 `/var/www/html/images/` 下的文件
   - 重新 publish（产生新 Media ID，告知用户）
   - 告知用户"配图纪律已写入 skill"——用户要求动作做到位，不只是本次改

根据文章**中心思想**匹配图片，不是固定配外贸图：

| 话题 | 配图方向 | 图源 |
|------|----------|------|
| 财税政策/法规解读 | 政府大楼、公章、文件 | Unsplash/下载到服务器 |
| 公司注册/创业 | 写字楼、办公场景、营业执照 | Unsplash |
| 出口退税/外贸 | 港口、集装箱、货轮 | ✅ /tmp/cover_cargo.jpg 可用 |
| 节税筹划/税务合规 | 计算器、图表、财务分析 | Unsplash |
| 跨境电商 | 电脑、手机、线上购物 | Unsplash |
| 代理记账/会计 | 财务报表、数字、办公室 | Unsplash |
| 政策通知/提醒 | 日历、时钟、公告栏 | Unsplash |
| 通用/综合 | 财税相关中性图 | Unsplash |

**配图执行流程：**
1. **封面图**：按「话题→配图方向」表精准选图。**每篇文章封面不能重复**，必须匹配中心思想（用户会直接退回通用图/重复图）。
2. **正文配图**：每篇文章**至少2～3张**正文配图。每张图放在对应章节位置，匹配该节的中心思想。
3. 从 Unsplash 搜索相关图片下载到阿里云服务器
4. **正文配图统一用 nginx 图片服务方案**（详见下方「✅ 方案A实操步骤」），不能用 asset:// 协议。
5. 若 Unsplash 下载失败，fallback 到 jsDelivr CDN 图片

**服务器下载命令：**
```bash
curl -L -o /tmp/cover_article.jpg "https://images.unsplash.com/photo-XXXX?w=800&q=80"
```

### 第3步：发布

**⚠️ 发布前检查清单：**

## 视频→文章 分支工作流（2026.7.26 新增）

适用场景：用户发送抖音/YouTube/B站等平台视频链接，基于视频内容创作公众号文章。

### 流程总览

```
用户发链接
  ↓
阶段1：内容提取（按平台匹配方法）
  ↓
阶段2：商量结构（出结构方案 → 用户确认/调整）
  ↓
阶段3：写初稿（含颜色标记重点）
  ↓
阶段4：配图 + 发布（复用主流程第2-3步）
  ↓
阶段5：固化经验到 skill（新增参考模板）
```

### 阶段1：内容提取

按平台分策略：

| 平台 | 方法 | 说明 |
|:-----|:-----|:-----|
| **YouTube** | `youtube-content` skill → `fetch_transcript.py` 拉字幕 | 最省力，直接出逐字稿 |
| **抖音** | 浏览器访问视频页 → 提取"章节要点"区域文案 | 视频页有结构化章节总结（已验证：2026.7.26 中国税务报视频） |
| **抖音（无章节）** | 用户下载视频文件 → `ffmpeg + faster-whisper` 语音转文字 | 备选方案，需要用户配合 |
| **B站** | 浏览器访问 → 提取视频简介/评论区/字幕 | 反爬较轻 |
| **网页/公众号文章** | 浏览器/curl 直接提取 | 最直接 |

**抖音提取要点**（已验证可行）：
- 抖音网页版可以加载视频详情页，但会触发登录弹窗
- 核心内容在"章节要点"区域（如果有章节功能的话），包含完整的结构化总结
- 视频标题、发布时间、发布者信息也可获取
- 评论区热评可作为"开头钩子"素材

### 阶段2：商量文章结构

内容提取后，必须在写作前与用户确认以下要素：

```
① 文章方向（给2-5个选项让用户选）
   - 纯深度解析（逐条展开）
   - 反差制造（"你以为没事其实触刑"）
   - 热点借势（官方号都拍视频了→信号）
   - 组合路线（上半篇普法+下半篇实操）⭐ 推荐

② 标题风格（给3个候选）
   - 热点借势型
   - 数据冲击型
   - 焦虑驱动型

③ 营销+GEO目的
   - 是否需要插入营销钩子（默认需要）
   - GEO段落强制添加（标准段落在本skill已有）

④ 颜色标记偏好
   - 关键数字/金额用红字（<span style="color:#CC0000;">）
   - 最核心概念红字加粗（<span style="color:#CC0000;font-weight:bold;">）
```

### 阶段3：写作规范

**沿用主流程的写作规范**（摘要120字、结构、GEO段落、品牌落款），额外增加：

**彩色文字标记技术：**
```html
<!-- 重要数字 → 红色 -->
<span style="color:#CC0000;">10万元</span>

<!-- 最关键概念 → 红色加粗 -->
<span style="color:#CC0000;font-weight:bold;">为他人、为自己、让他人为自己、介绍他人</span>

<!-- 段落标题序号 → 红色（配合 ## 标题使用） -->
## <span style="color:#CC0000;">一、</span>这里写标题内容
## <span style="color:#CC0000;">二、</span>这里写标题内容
```
在 wenyan + 安信伯君主题下，红色文字能正常渲染到微信文章。

**段落标题样式规范（2026.7.26 定稿）：**
- 文章内 `##` 一级章节标题，**序号部分用红色**，标题正文保持加粗
- 示例：`## <span style="color:#CC0000;">一、</span>先说清楚...`
- 色号统一 `#CC0000`，与正文关键数字的红色一致
- 不使用下划线（微信里像超链接，过时感）
- 不整行全红（与安信伯君风格冲突）

**配图原则（结合视频主题）：**
- 封面图：匹配视频核心主题（如法律类用：法槌、公章、文件）
- 正文配图：至少2-3张，每张对应一个章节
- ⭐ **增加冲击力配图**：话题涉及"坐牢/判刑/行政处罚"时，加一张监狱/手铐类强冲击配图（2026.7.26 用户指定）
- 配图尺寸：Unsplash `w=800&q=80` 标准

### 阶段4：发布

复用主流程第2步（配图）+ 第3步（发布）。

命令不变：
```bash
NODE_OPTIONS='--experimental-require-module' \
node /usr/lib/node_modules/@wenyan-md/cli/dist/cli.js \
publish -f /tmp/article.md \
--server http://127.0.0.1:3000 \
-c /etc/wenyan/yingxin-theme.css
```

### 阶段5：固化

每完成一轮"视频→文章"生产后，将本篇文章作为参考模板存档：
1. 保存文章到 `references/`（命名：`article-video-<主题>-<日期>.md`）
2. 在下方"已验证的视频→文章案例"表中追加记录
3. 如果流程有新发现（如某个平台的新提取方法），更新本分支工作流

### 风格拆解流程（用户发链接时）

当用户说"找到一篇排版好看的公众号文章"时：

1. 用户回复公众号文章链接
2. 用浏览器/curl打开链接，分析排版要素：
   - 正文字体大小、行间距

   - 配色方案（主色、强调色）

### ⚠️ 正文配图的已知限制（2026-06-30 已验证）

`wenyan publish` CLI **不支持在正文中使用 `asset://` 协议引用图片**。如果 markdown 正文里有 `![alt](asset://xxx.jpg)`，发布会失败（WeChat 错误码 40113）。

**正文配图的可行方案（按推荐优先级）：**

| 方案 | 操作 | 说明 |
|:-----|:-----|:-----|
| ✅ A. 阿里云ECS本地nginx服务 | 在服务器上搭建nginx图片直链 → `![](http://localhost:8080/images/xxx.jpg)` | wenyan原生支持，自动化，已验证可用 |
| B. HTTPS直链（阿里云OSS等） | 把图传到图床，正文用 `![](https://...)` | 可靠但需额外配置CDN |
| C. 后台上传 | 先发到草稿箱（不含正文图），让用户进公众号后台手工插入 | 最简单，但用户不喜欢 |

### ✅ 方案A实操步骤（2026-06-30 验证通过）

**核心原理：** 在阿里云ECS上搭nginx静态文件服务（端口8080），从Unsplash下载主题相关图片放入服务目录，markdown正文中用 `http://127.0.0.1:8080/images/xxx.jpg` 引用。wenyan publish 时自动抓取图片上传到微信CDN，文章发布后图片走微信HTTPS。

**一键安装/检查：** `scripts/setup-nginx-image-server.sh setup`（首次），`scripts/setup-nginx-image-server.sh check`（日常检查）

**① 确保nginx安装并配置图片服务**

```bash
cat > /etc/nginx/sites-available/images << 'EOF'
server {
    listen 8080;
    root /var/www/html;
    index index.html;
    server_name _;
    location / {
        try_files $uri $uri/ =404;
        add_header Access-Control-Allow-Origin *;
    }
}
EOF
ln -sf /etc/nginx/sites-available/images /etc/nginx/sites-enabled/images
nginx -t && systemctl reload nginx
```

**② 下载图片并放入服务目录**

```bash
mkdir -p /var/www/html/images
# 封面图（按话题→配图方向表精准选图）
curl -L -o /var/www/html/images/cover.jpg "https://images.unsplash.com/photo-XXXX?w=800&q=80"
# 正文配图（每张配图对应一个章节的主题，不能通用）
curl -L -o /var/www/html/images/section1.jpg "https://images.unsplash.com/photo-XXXX?w=800&q=80"
```

**③ 在 markdown 中引用**

frontmatter 封面改为 HTTP 直链：
```yaml
cover: http://localhost:8080/images/cover.jpg
```

正文配图用标准 markdown 语法：
```markdown
![配图说明](http://localhost:8080/images/section1.jpg)
```

**④ 直接 publish** — wenyan 自动抓取图片并上传微信CDN。

- 每张配图必须**匹配它所在章节的中心思想**（用户会直接退回通用图）
