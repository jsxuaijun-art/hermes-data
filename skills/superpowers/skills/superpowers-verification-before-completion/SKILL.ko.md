# 완료 전 검증

## 개요

검증 없이 완료를 주장하는 것은 효율이 아니라 부정확함입니다.

핵심 원칙: 주장보다 증거가 먼저입니다.

## 철칙

```text
최신 검증 evidence 없이 완료 주장 금지
```

이번 turn에서 검증 명령을 실행하지 않았다면 "통과했습니다", "완료했습니다", "고쳤습니다"라고 말할 수 없습니다.

## Gate

완료 상태를 말하기 전에:

1. 관련 검증 명령을 정합니다.
2. 명령을 실행합니다.
3. output을 확인합니다.
4. 실패하면 완료 주장을 하지 않습니다.
5. 통과하면 어떤 명령이 통과했는지 말합니다.

## 검증 명령 선택

가능한 가장 직접적인 검증부터 실행합니다.

- code change: 관련 unit test, integration test
- bug fix: regression test
- build issue: build command
- lint issue: lint command
- docs 또는 config: parser, formatter, targeted smoke check

그 다음 필요하면 전체 suite를 실행합니다.

## 검증할 수 없을 때

검증을 실행할 수 없다면 다음을 명확히 말합니다.

- 어떤 명령을 실행하려 했는지
- 왜 실행할 수 없었는지
- 대신 무엇을 확인했는지
- 남은 위험이 무엇인지

실행하지 않은 것을 실행한 것처럼 말하지 않습니다.

## 금지 표현

검증 전에는 다음 표현을 쓰지 않습니다.

- 완료했습니다.
- 고쳤습니다.
- 통과합니다.
- 문제 없습니다.
- 준비됐습니다.

대신:

- 변경을 적용했습니다. 지금 검증하겠습니다.
- 관련 테스트를 실행해야 완료 여부를 말할 수 있습니다.

## 실패 시

검증이 실패하면:

1. 실패 output을 읽습니다.
2. root cause가 불분명하면 `superpowers-systematic-debugging`을 사용합니다.
3. 수정합니다.
4. 같은 검증을 다시 실행합니다.

## 완료 보고 형식

```text
검증:
- <명령>: 통과

변경:
- <요약>

남은 위험:
- <있으면 기록>
```

검증이 일부만 가능했다면 "부분 검증"이라고 분명히 표시합니다.
