# 官方来源截图配图：找链接与截图的实操参考

> 定位：`SKILL.md`「官方报道/政策文件截图法」配图铁律的操作细则。**用户常在出稿后追加一句"把税务局官网的报道链接找出来，我去截图"** —— 这一步不是可选项，要当成交付环节直接做掉。

## 0. 用户真正要什么

用户说"我去截图"，需要的是**能直接打开、有官网红头/官方 UI、内容与文中数字一致的页面**，不是二手转载站的同文。
所以输出必须分层：
1. 官网直达链接（首选，给 2 条更好：短通报 + 长揭秘，分别适合配"处罚结果"段和"作案手法"段）
2. 官网栏目页（当直链找不到时，让用户自己翻一页点进去）
3. 一字未改的转载页（标注来源为官方号的，只作兜底）

每一条都要**自己先抓取正文、核对与文章里的数字/法条文号一致**再给用户，不能只贴 URL 说"自己看"。

## 1. 定位省级/市级税务局官网通报的搜索套路

案件通报类稿件的稳定位置：省级税务局官网「新闻动态 → 税务新闻」栏目，标题多为《…税务局第X稽查局依法查处…案件》或《…揭秘…案件》。

按这个顺序试，**前一步命中就停，不要全跑一遍**：

```bash
# ① 通用搜索引擎先探标题（带上案件关键实体，别只搜"税务局"）
#    查询式："<涉事公司全名>" <稽查局> <案件关键词>
# ② 限域名搜索，能直接命中就把该 URL 交给 web_extract 验证正文
#    site:<省>.chinatax.gov.cn <公司名>
#    site:chinatax.gov.cn <公司名>
# ③ 搜索引擎未收录时，抓栏目列表页找 art_ 链接
#    <省>.chinatax.gov.cn/col/colXXXXX/index.html   （税务新闻栏目固定是 art_<栏目ID>_<文章ID>.html）
```

**国家总局站（www.chinatax.gov.cn）收录更全**，同一案件常有两篇：短通报 `c<ID>/content.html` 与 长揭秘（标题含"揭秘/现形记/黑中介"）。总局站能搜到时优先给总局链接——不用过省级站的 WAF。

## 2. 官网上了动态验证（瑞数 WAF）怎么办

**症状**：`curl` 抓栏目页只回 ~3KB，正文里是 `$_ts` 变量 + 一段混淆 JS，没有任何 `art_` 链接；`r.jina.ai` 代理同样空手。这是瑞数（RS）反爬在客户端算 cookie，纯 HTTP 抓不到，**不是链接不存在**。

**不要做的事**（浪费轮次、还容易把错误结论当事实告诉用户）：
- ❌ 反复换 UA / Referer / 加 `-L` / 换 http↔https —— 瑞数校验的不是 UA
- ❌ 改用 `anysearch`、裁判文书网检索继续捞 —— 那几个通道拿到的是**同案名但不同案件**的判决书（同名公司/同类虚开极多），混进去就是幻觉
- ❌ 硬猜 `art_2026/11/11/art_10968_XXXXXX.html` 的文章 ID —— 猜中的概率≈0，猜错还浪费验证轮次

**正确处置（照做）**：
1. 坦白一句：该官网有动态验证，抓不到直链（一句话，不解释技术细节，不过度道歉）
2. 给栏目页 URL，说明"翻到 X 月 X 日那篇"——用户本人在浏览器正常打开不会被拦
3. 给一字未改的转载页兜底（正文里注明"来源：<官方号>"的那种），并明确说清"这份是转载，来源标注为官方"
4. 提醒：用户手上的官方视频号/官方媒体发布截图同样可用
5. 收尾提议：只要用户把浏览器地址栏链接复制回来，就能帮他存成桌面图片一并配图

**绝不把"抓不到"包装成"找不到"，也不要把转载页说成官网页。**

## 3. 交付格式（用户拿去截图，扫一眼就能动手）

按案件分段，每条链接下面一行说明这条适合配哪一段：

```
一、<地区>·<主体>案（官网已验证可打开）
1）案件通报（短版，适合配"处罚结果"）
<URL>
2）深度揭秘（长版，含办案过程/法条原文，适合配"作案手法"）
<URL>

二、<地区>·<主体>案（官网有动态验证，无法给直链）
问题：一句话。
办法①栏目页 <URL>，翻到 <日期> 那篇
办法②转载兜底 <URL>（来源标注为 <官方号>）
```

再附一个「建议截图方案」小节，直接指派：封面/首案截哪条、次案截哪条，省掉用户自己权衡。

## 4. 配图与事实一致性

- 截图来源必须与文中数字、法条文号逐一对上（如 16.50 万 / 3.54 万 / 征管法 63 条、实施细则 93 条）。挂错案件的官网截图比无图更糟。
- 同一篇文章涉及多个案件时，**每个案件各截各的官方页面**，天然满足"禁复用"铁律，不要拿其中一案的截图通配全文。
- 截图路径常在 `D:\360MoveData\...\Desktop`，先按实际存在读取。

## 5. 用户回头要「上次那篇的官网链接」（换会话续作）

用户会在隔天/换会话后重新要链接（“调取关闭前的任务”、"上次那个案件的官网链接"），此时会话里的 URL 可能已被清理。**不要重新搜一遍、更不要换一个「类似案件」凑数**——同案名不同案（同名公司/同类虚开极多）是这一环节最大的幻觉源。

1. `session_search(query=<案件名/公司名>, sort="newest")` 捞回原会话；`session_search(session_id=..., around_message_id=...)` 滚到给链接那段，原样复用已核验过的 URL 与"哪条适合配哪段"的指派。
2. 复用前当场重验一次：`curl -s -o out.html -w "%{http_code}" <URL>`，HTTP 200 + `<title>` 命中案件名才算仍然有效（政府站会改版、旧 `t48xxxx.html` 是真实路径不是猜的）。
3. 同一篇里的另一案如果当初就卡在 WAF（如宁夏站），续作时**直接重申栏目页 + 转载兜底**，不要重新试探一轮——那只会重复浪费轮次，结论不会变。
4. 交付形态：一条案一段，标明「已验证可打开」或「有动态验证」，末尾附建议截图方案；用户接着就要配图，别让他再问一遍。
