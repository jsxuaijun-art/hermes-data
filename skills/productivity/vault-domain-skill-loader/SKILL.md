# Vault 领域技能加载器

## When to Use

- 用户提到**税务稽查 / 税务检查 / 稽查应对 / 收到《税务检查通知书》《税务行政处罚事项告知书》《税务处理决定书》**等 → 走 tax-audit-response 加载流程
- 用户直接给出 `50-Skills/` 下的路径或文件名 → 按对应启动器加载
- 禁止用本技能覆盖的知识直接作答税务问题——必须先把 vault 启动器和文件读完

## 背景

用户把**专业领域技能**存在 Obsidian 知识库里（`/mnt/d/obsidian-vault/50-Skills/<技能名>/`），不在 Hermes 的 `~/.hermes/skills`。每个技能目录有一个 `HERMES-启动提示词.md` 启动器，规定：角色、必须按序读取的文件清单、固定回复语、工作流程、红线。

这些技能是**用户自有资产**：只读加载，**绝不写入/修改** vault 内的技能文件。

## 已登记技能

| 目录 | 领域 | 首轮加载文件数 |
|---|---|---|
| tax-audit-response | 税务稽查/税务检查应对（盈信代理客户，苏州/上海中小微） | SKILL.md + references/01-04 = **5 个** |

tax-audit-response 目录结构：`SKILL.md`、`HERMES-启动提示词.md`、`references/01~04`（阶段文书对照与要素清单 / 法律依据速查 / 文书写作铁律与自检清单 / 常见案由论证要点）、`templates/01~06`（情况说明 / 陈述申辩意见书 / 听证申请书 / 分期或延期缴纳罚款申请 / 税务行政复议申请书 / 自查报告）、`cases/`（脱敏案例库，办完案按 `_案例模板.md` 存 `YYYY-MM-案由关键词.md`）。

## 加载协议（必须遵守）

1. 用户给出路径或提到该领域时，先 `read_file` 启动器本身，**以启动器清单为准**。
2. 按启动器列出的路径**逐个**读取（顺序不能跳），不许凭记忆或通用知识作答税务问题。
3. 读完回复启动器规定的固定语句。tax-audit-response 为：
   `已加载，共 N 个文件，请给我案情。`
   - **N = 实际读取的文件总数，必须包含 SKILL.md**。tax-audit-response 首轮 = 5（SKILL.md + 4 个 references）。坑：数漏 SKILL.md 会报错 4，导致 N 与实际不符。
4. 文件读不到 → 原样回复 `无法访问 /mnt/d/obsidian-vault/50-Skills/`，并列出实际可访问的 skills 目录。**严禁假装读过、严禁编造税务内容。**
5. 需要写文书时，再读 `templates/` 下对应的那个文件；先过 `references/` 判断案由/阶段是否已在册。

## tax-audit-response 执行提示（详情以启动器和 SKILL.md 为准）

收到案情后顺序不能跳：① 判断阶段（口头通知／检查通知书／调取账簿／处罚告知书／处理决定书——阶段决定空间）→ ② 采集要素（缺一项先问，不许脑补）→ ③ 分析定性（追征期 → 定性之争 > 金额之争 → 程序瑕疵 → 从轻情节 → **先查 references/04 有没有对应案由**）→ ④ 选模板写文书（遵守 references/03 十条铁律）→ ⑤ 自检清单逐条过。

红线（任何情况不得逾越）：
- 绝不建议/协助隐匿、转移、销毁账簿凭证（《稽查规定》27条 → 补税案升级处罚案）
- 绝不编造、变造证据，不诱导虚假陈述
- 绝不代替客户署名
- 涉刑预警（虚开专票 / 逃税数额较大且占应纳税额10%以上 / 拟移送公安 / 重大税务案件）→ 立即提示请律师或税务师，只做行政程序文书

输出要求：
- 文书正文**不用代码块包裹**（方便粘 Word）；待确认内容标 `【待确认：xxx】` 不许编；附件清单列文末
- 文书之后另起一段**给客户的内部提示**（不进正文）：风险点、可争取空间、下一步动作
- 存档 `/mnt/d/obsidian-vault/` 下，**不存 /tmp**

文书交付（docx）：
- 用户说「导出/生成 docx / 存桌面」→ 用 python-docx 导出到 Windows 桌面 `/mnt/c/Users/Admin/Desktop/`（WSL 路径，用户名 Admin），文件名如 `情况说明-<事项关键词>.docx`；先 `python3 -c "import docx"` 确认可用
- 格式惯例：正文宋体 12pt、标题 16pt 加粗居中、一节标题 13pt 加粗、段落首行缩进 24pt；金额/法条/证据编号照抄正文
- 文书内的 `【待确认：xxx】` 原样保留进 docx（客户自己搜「待确认」逐项替换），交付后提醒：对外提交前须持证人员（税务师/律师）复核

启动器底线规则里的四条硬知识（本 skill 不复述细节，用时以启动器与 references 为准）：
① 税率不许默认 25%——先确认是否小型微利企业（2023.1.1–2027.12.31 实际税负 5%）；② 滞纳金日万分之五、汇缴滞纳金自次年 6 月 1 日起算，测算给区间不给单一数字；③ 无票支出先走程序性补救（28 号公告第 15 条 60 日窗口、第 14 条凭资料证实真实性即允许扣除）——走通=一分税不用补，比谈从轻罚款高一个量级；④ 追征期给明确结论：2023 年度税款 2026 年无论 3 年/5 年均在期内，抗辩不成立，直接告知客户别抱错误期待。

法规在途变动（对外引用前核 references/02 维护提醒）：《税收征管法》修订草案 2026-08-31 国务院常务会议原则通过（拟取消复议清税前置、滞纳金更名税款迟纳金、新增无过错漏税情形）；《华东区域税务行政处罚裁量基准》2026 已启动修订——现行对外文书仍按现行法引用。
