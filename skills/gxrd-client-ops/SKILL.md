# 高企账务 + 研发费用加计扣除 · 乙方服务作战手册

## 0. 我的框架思想（先读，理解为什么这样组织）

> 源承：吴健《研发费用加计扣除与高新技术企业优惠实务及案例》(2024.3, 中国市场出版社, 404页扫描本) + 6 本源书蒸馏台账。
> 本技能是对既有「文档查表」型高企技能的**重构升级**，核心是 5 条设计原则，全部可运行、可回归、可跨会话续作：

| # | 原则 | 解决的问题 | 落地 |
|---|------|-----------|------|
| ① | **决策优先**（先路由再查文档） | 客户交叠多种情形（高企+集成电路+亏损+委托境外+复审年）时没有裁决顺序，只能人肉拼文档 | `scripts/gxrd_engine.py decide` 输出结论+路径+关卡 |
| ② | **证据驱动**（准入由证据完备度倒推） | 「能不能做」不该凭印象，而该由立项/辅助账/工时/领料四类证据是否齐全反推 | decide 的 evidence_gaps |
| ③ | **实例持久**（客户×年度可跨会话续作） | 没有客户实例状态，无法三年滚动、无法隔天续做 | 每个客户建 `clients/<客户>/<年度>.json` 作业实例 |
| ④ | **规则显式**（口径、限额、钩稽可执行） | 20%/10%、40行=2+36×80%+38、80%/2/3 写在散文里，机器不能据此校验 | `gxrd_engine.py calc` + `selfcheck` 回归集 |
| ⑤ | **政策时效**（带生效期自动失效） | 44号 120% 2027 到期不该靠 TODO 提醒 | `gxrd_engine.py policy --asof` 按日期裁决 |

> **工作快照**：遇到任何高企/加计问题，先跑 `decide` 定路径，再跑 `calc` 出数，最后按风险清单体检；三口径对照与 A107012 逐行见 references。被查转 `tax-audit-response`。

## 3. 标准工作流（先决策，再执行）

| 场景 | 入口 | 流程 |
|------|------|------|
| **S0 接客户/判断能不能做** | `decide` + `client_intake.md` + 尽调问卷 | 四关卡主体/行业/活动/证据 → 结论分级（直接做/整改/不做）→ 报价与责任边界 |
| **S1 首次建研发账** | `auxiliary_ledger.md` + assets | 选样式（推荐2021简化版）→ 设科目与项目辅助核算 → 定分摊方法 → 立项时设账 → 月末结转 → 年末汇总 |
| **S2 存量客户规范** | `client_intake` 整改方案 | 补立项与内控记录 → **从当期起设账**（不追补历史辅助账）→ 风险提示函 |
| **S3 加计扣除申报（非高企路径B）** | `rnd_superdeduction.md` + `calc` | 归集口径校验 → 限额计算 → 辅助账汇总 → 预缴/汇缴 A107012 → 留存备查 |
| **S4 高企认定/复审（路径A）** | `hte_certification.md` + `calc` | 三年占比滚动 → 高新收入≥60% → 科技人员≥10% → 专项审计衔接 → A107041 |
| **S5 汇缴与税会差异** | `accounting_tax_diff.md` + `calc` | 收入调整 → 加计抵减 → A105000 → 主表钩稽复算 |
| **S6 年度体检/风险自查** | `risk_checklist.md` + `calc` | 先跑金税量化预警 → 六类逐项打勾 → 案例对照 → 整改建议 |
| **S7 被查/异议鉴定** | → `tax-audit-response` | 本技能只准备鉴定材料与备查包 |

**测算一律走 `scripts/gxrd_engine.py`，不要凭心算：**
- `decide --profile '<json>'` 准入门槛判定（含负面清单兼营占比公式、证据缺口）
- `calc --json-text '<json>'` 全链计算（限额/分摊/委托/A107012 40行/加计）
- `policy --asof 2028-01-01` 政策时效（120% 到期自动排除）
- `selfcheck` 回归自检（含例4-1 三个锚点 + 政策时效）

## 4. 七条绝对红线（操作前必查）

1. **口径不能混用**：高企认定「其他费用≤20%」 vs 加计扣除「其他相关费用≤10%」，同一笔费用两套上限都要卡；加计限额自 2021 年度起按**全部项目统一计算**（2021年第28号），不再逐项目。
2. **高企 15% 与小微择一**，二者不可同时享；**加计扣除可叠加**。具体档位以电子税务局申报系统当年带出为准，不写死。
3. **辅助账是命根**：无辅助账=不得加计=高企复核不达标。必须**立项时设账**、年末汇总、随申报留存备查；**不得事后补账**。
4. **只有高企才能加计？错**：非高企客户照样 100% 加计；亏损企业可形成/扩大亏损结转；研发失败、跨年度项目当年费用化部分均可加计；未享受可追溯 3 年。
5. **自主研发无须事前鉴定或立项备案**（企业内部有权部门决议即可），但**委托/合作研发合同必须经科技行政主管部门登记**；有异议时由税务机关转请科技部门鉴定。
6. **高企客户是两套账、两套上限**：加计扣除 2021 版辅助账 ≠ 高企认定专用辅助账（按项目、近三年分年设账，需中介专项审计）。**研发费用占比分档依据「最近一年销售收入」**（不是近三年合计）；房屋折旧/租赁费、装备调试费、知识产权摊销三项两口径处理相反。
7. **申报前跑一遍金税系统量化预警**（`risk_checklist.md` §一/§二）：结构占比≥70% 或波动≥50%、加计额≥500万、高企证书非空而 A107012 第51行<1万等都会触发核查。命中≠违法，但必须提前备证。

## 5. 政策基线（速引，详看 policy_basis.md）

- 加计比例：**2023.1.1 起全行业 100%**（费用化 100% 加计 / 无形资产 200% 摊销，2023年第7号）；集成电路·工业母机 **120% / 220%**（2023年第44号，2023–2027，清单管理，资本化按摊销时点判断）。
- 预缴享受**三时点**：7月（上半年）、10月（前三季度）、汇算清缴；未选择可在后续时点统一享受（2023年第11号）。
- 其他相关费用限额 = 全部项目前五项之和 × 10%/(1−10%)；采取**正列举**，未列明费用不得计入。
- 高企优惠税率 **15%**；亏损结转 **10 年**；资格有效期 **3 年**；创新能力评价 **>70 分**；研发费占比分档按最近一年（5%/4%/3%）、境内研发费 ≥60%、高新收入 ≥60%、科技人员 ≥10%。
- 优惠办理：**自行判别、申报享受、资料留存备查**（2018年第23号）。
- 涉及税率、比例、金额、文号：**政策原文 > 源书 > OCR**；具体当年档位/表版本以电子税务局、12366 为准。

## 6. 蒸馏与维护

- 6 本源书蒸馏进度台账见 `references/book_distillation_log.md`（#5 吴健书已蒸馏，其余见 TODO）。
- 每蒸馏一本，更新台账并在对应模块标注「源书 + PDF 页码 + 政策文号」。
- 新增硬事实 → 在 `selfcheck` 黄金测试集补一条断言（这是「新框架更好」的可验证证据）。
- 客户作业实例：`clients/<客户代码>/<年度>.json`，运行 `decide`/`calc` 后保存结果，实现跨会话续作与三年滚动。
- **引擎读 profile 两形状必须都兼容**：`decide --profile` 既收顶层内联 dict（快速测试），也收「客户作业实例模板/实例 JSON」（字段在 `profile` 下、状态在 `meta` 下）。加载入口先做形状归一化再路由——只测内联 dict 会漏掉模板文件这条路径，判定会静默反转但 selfcheck 数值锚点照绿（一次真把「高企+证据齐」误判成「整改后做」）。改模板结构与 `cmd_decide`/`cmd_calc` 后，必须用真实模板文件重跑一遍 `decide` 验证路径与结论。

## 7. 诚实的边界

- 本技能不替代专项审计/鉴证报告；不承诺认定或稽查结果。
- `accounting_tax_diff.md` 的汇缴主线仍待冯秀娟《一案解析》(台账#4) 补全。
- 政策参数不写死；当年税率、申报表版本、清单管理以电子税务局与主管部门公告为准。
