# 脱敏处理 Skill

## When to Use

- 用户上传/粘贴任何含主体信息的材料（Word、Excel、PDF、截图、文字）并要你读取、分析、整理、写入文档时
- 对话或文档中出现具体公司名称、统一社会信用代码、法定代表人姓名、身份证号时
- 任何要写入 skill 库、同步仓库、公开示例、案例库的内容
- 用户提到"脱敏""敏感信息""数据安全"时

## 用途

用户上传的任何材料（文字、Word、Excel、PDF、截图、其他文件格式），凡涉及下列四类敏感主体信息，一律**先自动脱敏、再进入对话/分析/写作/入库/同步**：

1. 具体公司名称
2. 统一社会信用代码
3. 法定代表人姓名
4. 身份证号

**为什么必须前置**：文件本身保存在用户本地磁盘，不会上传给模型提供商；但读取后的文字会进入对话上下文，每一轮都作为 API 请求发给模型提供商（如 DeepSeek），且对话前缀可能被提供商缓存。真实文字一旦进对话即已外发、不可撤回。因此脱敏必须在**读取前/进入上下文前**完成。真实版本只允许出现在本地交付物（如提交税务机关的报告），不允许出现在公开仓库、skill 库、同步内容。

> ⚠️ 本 skill 内的示例一律使用**虚构主体/占位符**，绝不放真实主体当示例——本 skill 自身也在推送前 `leak_scan.py` 扫描范围内。

## 自动兜底：desensitize-read 插件（已启用）

本 skill 是**策略层**（我来执行规则）；`desensitize-read` 插件是**执行层**（读入即拦，不依赖我是否记得），二者配合实现"出现即自动脱敏、无需手动调用"。

- 位置：`~/.hermes/plugins/desensitize-read/`（已随 `hermes_push.sh` 同步到各设备）
- 机制：挂 `transform_tool_result` 钩子——「读入型」工具（read_file / search_files / web_extract / web_search / terminal / execute_code / browser_* / vision_analyze）的结果，在进入模型上下文**之前**自动脱敏；只作用于外部读入内容，不改 agent 自身产出（write_file/patch/skill_manage）
- 自动执行的规则：① 词表精确替换（`~/.hermes/leak-blocklist.txt`，`真实=脱敏` 格式）② 信用代码末8位→X ③ 身份证号中间8位→X ④ 法定身份字段（法定代表人/负责人/股东/投资人/联系人/办税人…：）后的姓名前两字→T
- 启用：`hermes plugins enable desensitize-read`（写入 config.yaml 的 `plugins.enabled`）；**下次会话生效**，每台设备各自执行一次
- 关闭：环境变量 `DESENSITIZE_READ_DISABLE=1`；自定义目标工具：`DESENSITIZE_READ_TOOLS=read_file,terminal`
- 边界：只拦"工具读取的内容"，我已读入的历史上下文它管不到；游离出现的姓名（无标准字段前缀）认不出，靠词表兜底
- 接新客户：把真实公司全名/简称/信用代码/法人名按 `真实=脱敏` 追加进 `~/.hermes/leak-blocklist.txt`（该文件在 ~/.hermes 根目录、**不推送**，含真实值安全）

**三层防线**：
1. **读取时** — desensitize-read 插件自动脱敏（本机一切会话，含我自己读文件）
2. **我执行时** — 本 skill 规则（记忆注入+触发词，无需手动喊）
3. **推送时** — `hermes_push.sh` 的 `leak_scan.py` 扫描，命中即中止推送

## 脱敏规则（硬性，用户定稿）

### ① 公司名称
除组织形式后缀外，其余汉字一律转为**拼音首字母（大写）**。组织形式后缀保留：`有限公司`、`（有限合伙）`、`合伙企业`、`公司`、`集团` 等。

| 原名称（虚构示例） | 脱敏结果 |
|---|---|
| 甲乙丙丁（苏州）有限公司 | JYBD（SZ）有限公司 |
| 星云传动（上海）合伙企业（有限合伙） | XYCD（SH）（有限合伙） |

方法：逐字取拼音首字母（zh→Z、ch→C、sh→S、ü→V/U），字母全部大写；括号内行政区划同样取首字母（苏州→SZ）。公司**简称**同样脱敏：甲乙丙丁 → JYBD。

### ② 统一社会信用代码（18位）
**保留前10位，末8位全部用 X 代替（总长保持18位）。**
写法示例（不写完整真实码，避免形成码形）：`AA12345678`（前10位保留）＋ `XXXXXXXX`（末8位打码）＝ 18位。凡末8位不是全 X 的 18 位码，一律视为未脱敏。

### ③ 法定代表人姓名
**前两个字都用 T 代替。**
例：杨建国 → TT国；王芳 → TT（两字名则全部打码）

### ④ 身份证号（18位）
保留前6位（行政区划）与后4位（顺序码+校验码），中间8位（出生日期）用 X 代替。
写法示例：`320504`（前6位保留）＋ `XXXXXXXX`（出生日期打码）＋ `1234`（后4位保留）。

## 工作流程

```
① 识别   通读材料，列出全部真实主体信息清单（公司名/简称/信用代码/法人/身份证）
② 脱敏   对材料副本应用上述规则（逐项替换，简称一并处理）
③ 处理   用脱敏副本进入对话/分析/写作，绝不引用真实值
④ 交付   本地交付物保留真实版(如提交税局的报告)；公开/入库/同步版一律用脱敏版
⑤ 验证   在产物中检查真实值0残留（见验证）
```

## 验证（硬性）

进入公开仓库 / skill 库 / 同步内容之前，必须验证：

```bash
# 产物目录内真实值残留应全部为 0
grep -rl "真实公司名" <目录> | wc -l     # 应为 0
grep -rl "真实信用代码" <目录> | wc -l   # 应为 0
grep -rl "真实法人名" <目录> | wc -l     # 应为 0
# 同时确认脱敏形式已出现
grep -l "GFSBDT（SZ）有限公司" <目录> | wc -l  # 应 ≥1
```

若推送过含真实身份的历史版本到 GitHub，按 `hermes-data-sync` skill 流程重新推送脱敏版，并全仓库 `git grep` 复查 0 残留。推送前 `hermes_push.sh` 会自动跑 `leak_scan.py`（正则+本地词表 `~/.hermes/leak-blocklist.txt`），命中即中止推送。

## Pitfalls

1. **脱敏必须前置**：已进对话的真实信息无法撤回（已发给提供商）。事后补救只能清存量（本地产物、公开仓库），救不回已发送的上下文。
2. **简称与全称都要脱敏**：只改全称、漏掉简称（如"X公司承诺…"）等于没脱。
3. **交付物例外**：客户真实提交版（如自查报告 docx）必须含真实主体才能递交——这是业务需要，与"公开/入库/同步版必须脱敏"不冲突；交付真实版时用本地路径交付，不入公开仓库。
4. **历史存量**：已有 skill/示例可能含真实身份（本会话即从公开仓库清理过2处），新规则生效后先全库扫描一遍再推送。
5. **示例必须虚构**：任何写入 skill/文档的示例都要用虚构主体（见上方示例），绝不用真实客户当例子。
6. **拼音容易写错**：取首字母时注意整体认读（如"苏州"=SZ 不是 SZHOU）；不确定就用逐字对照。
7. **脱敏码长度**：信用代码脱敏后必须仍是18位（前10保留＋末8X）；写错长度（如11位保留）会被扫描器当成未脱敏拦截。
8. **数字格式**：脱敏不改变金额/日期等业务数字，不与其他格式规则（Times New Roman、千分位）冲突。
