# 名册/公示表统计口径核验（Roster Statistics Verification）

**适用**：任何"从多页 PDF 名册/公示表里统计出来的数字"——"通过 X 人"
"某类单位占 Y%""参评 N 人评上 M 人"——且将被引用进对外材料
（公众号、话术、PPT、报告、短视频文案）时，用本流程把它钉死在原始文件上。

> 触发场景：高会/税务师/注会评审名单、政府采购中标名单、各类资质公示名单、
> 获奖名单……任何"一页一个人、跨几十页"的 PDF。

> 与占位纪律的关系：本文件是**铁律 3「先核实再引用」在"统计数字"这一类
> 材料上的具体执行法**。统计数字比政策文号更阴险——它读起来最像事实，
> 却最容易因为一个解析错误全盘漂移。

---

## 核心原则

**统计口径必须能用脚本从原始文件重放出同样结果。**
重放不出来 = 这个数字不能对外用，无论它当初是谁写的、写在哪。

## 最大的风险：统计数字会被复制进几十个副本

本项目的人设锚点类数字会被**复制进几十个 skill 副本与对外材料**
（人设、话术、产品手册、公众号、GEO、短视频文案……依赖清单见
`~/.hermes/skills/skills/compliant-accounting/references/canonical-identity-anchor.md`
§六 引用依赖图谱）。

**写进去的成本是 1，撤回来的成本是 40+。** 所以统计数字入稿前必须先过本流程，
不要等到有人质疑才回头核。

---

## Step 1 — 定位原始文件，把自己锚死在它上面

先找原始 PDF，不要接受二手转述的数字。

已知会藏原始材料的路径：

- **企业微信缓存**：`/mnt/d/OneDrive/文档/WXWork/<企业ID>/Cache/File/<YYYY-MM>/*.pdf`
  ——用户从微信/企微发来的文件默认落这里，是最常见的"原始件"来源。
- 桌面 / 下载 / OneDrive 文档 / Obsidian `_AI-Private/`

```bash
# 按文件名关键词定点查（别扫全盘，会超时）
find /mnt/d/OneDrive/文档/WXWork -iname '*评审*' -o -iname '*公示*' 2>/dev/null
```

## Step 2 — 抽取文本，先确认「人」这个计数单位对上了

```python
import pymupdf, re
doc = pymupdf.open(path)
raw = "\n".join(p.get_text() for p in doc)
open("/tmp/all.txt","w").write(raw)
```

公示表每页带页码页脚（`第 N 页，共 M 页`），**先剔除**再解析，
否则页码会被当成序号：

```python
lines = [l.rstrip() for l in raw.splitlines()]
clean = [l for l in lines
         if not re.match(r"^第\s*\d+\s*页，共\s*\d+\s*页", l.strip()) and l.strip()]
```

⚠️ **最容易错的一步**：PDF 里**没有出现"1"和"2"两个序号**——表格标题行和表头
被抽成了别的形状，或第 1、2 行跟表头粘在一起。所以：

```python
# 不要断言从 1 开始；从 3 开始扫，看总数是否等于公告声称的人数
expected = 3
records = {}
cur, buf = None, []
for l in clean:
    s = l.strip()
    if s == str(expected):
        if cur is not None: records[cur] = buf
        cur, buf, expected = expected, [], expected + 1
    elif cur is not None:
        buf.append(s)
if cur is not None: records[cur] = buf
```

**验收条件**：`len(records)` 加上缺失的前两条 == 公告自己写的总人数
（例：文件名写"（1999人公示）"→ 应得 1997 条 + 前 2 条 = 1999）。
对不上说明序号锚点漂了，**别继续统计**，回去查抽取。

## Step 3 — 记录边界用「序号 == 下一位整数」做锚

为什么不用正则切字段：**单位名会折行**。扁平化后一条记录长这样：

```
945 智慧园财税咨询（苏州）有限公司 李新梅 女 南京财经大学 本科 20061009 …
     ↑ 序号   ↑ 单位名            ↑ 姓名  ↑ 性别 …
```

单位名可能被 PDF 拆成 2 行（`中国医学科学院皮肤病医院（中国医学科学院皮肤` /
`病研究所）`），所以**只有当行内容恰好等于"下一个整数"时才认为是新记录起点**——
单位名或姓名里不会单独出现一个裸整数。

把解析结果 dump 成 JSON 存盘，后续所有口径统计都从这份 JSON 重放：

```python
json.dump({str(k): v for k, v in records.items()},
          open("/tmp/recs.json", "w"), ensure_ascii=False)
```

## Step 4 — 口径归类的三条铁律

统计"某类单位有多少"最容易被**名称字面**骗到。三条：

① **别只搜一个关键词。** 「代理记账」在整套名单里出现 0 次是正常的——
   这类公司注册名普遍叫「XX企业管理有限公司」「XX财税服务有限公司」
   「XX财务咨询有限公司」「XX会计服务有限公司」「XX记账服务有限公司」。
   要扫的是一个**词族**，不是一个词。

② **「财务」类名称绝大多数不是代账公司。** 实测同一份名单里含"财务"的 9 家是：
   教育财务结算中心、交通控股集团财务有限公司（×2）、农村财务服务中心（×2）、
   体育财务结算中心、医疗卫生机构财务集中核算中心、集团财务有限公司、
   财务咨询管理公司——**只有最后一家真属于代账/财税服务**。
   凡是「XX中心」「XX集团公司财务有限公司」「结算中心」「核算中心」一律不是。

③ **"会计服务"要区分内部记账机构。** 如「南通市自然资源会计服务中心」是
   机关事业单位的内部核算机构，不是对外经营的代账公司。

分类后**逐家列出**（单位名 + 姓名 + 市别 + 通过/未通过），让用户能自己复核，
而不是只给一个汇总数字。

## Step 5 — 交叉核对：用另一份名单反证

通过率类口径需要**两份文件**：

- 《…评审情况一览表（N人公示）》= 参评全量（含未通过）
- 《…评审通过人员名单》= 通过集合

做法：解析出通过集合，再遍历参评记录：
`单位含关键词 and 姓名 in passed_names` → 该家通过。
**不能只按单位名匹配**（同一家公司可能多人参评，如「无锡市新融企业管理发展集团
有限公司」2 人、「如东县农村财务服务中心」4 人），必须 **单位 + 姓名** 成对判定。

## Step 6 — 结论交付要求

给出统计数字时必须同时给：

1. **可重放的脚本路径 + 中间产物路径**（`/tmp/recs.json` 之类）
2. **命中明细清单**（哪几家、谁、通过与否），不是只有汇总
3. **一句话说明分类判据**（"我按单位名称判定是否为对外经营代账/财税服务公司"）
4. **未决项**：名称看不出性质的（如纯「XX管理咨询有限公司」）单独列为
   "性质待定"，不计入分子也不计入分母，并说明会影响哪个方向

## Pitfalls

- **别扫全盘找文件。** 宽范围 `find /mnt/d -iname '*x*'` 实测 180s 未返回。
  按已知路径定点查（企微缓存目录、桌面、下载、OneDrive）。
- **PDF 有表格结构 ≠ 文本抽出来还能用。** 可以试 `page.find_tables()`，
  但很多中文公示表的表格线是装饰性的，抽出来行错位；文本流 + 序号锚点更稳。
- **序号锚点从 3 开始，不是 1。** 见 Step 2。
- **单位名折行**是最大干扰——永远用"裸整数 == 下一个序号"判记录边界。
- **不要在核对完成前把数字写进任何 skill/话术。** 撤回成本 40+ 文件。

## 若核验失败：已扩散到副本的统计数字怎么处置

一个已写进人设/话术/公众号的统计数字，若重放不出来，处理纪律是：

1. **先暂停引用**——尤其对客话术和公众号，宁可少说不能说错。
2. **向用户明确报告"这组数字我复现不出来"**，并给出你能确证的裸数据
   （直接从公告人数得来的数字通常是稳的，如"全省 1999 人参评 / 1336 人获评 /
   663 人被拒 / 整体 66.8%"）。
3. **把存疑数字标"待核实"**，不要静默删除也不要静默保留。
4. 让用户定夺口径（可能原口径另有筛选条件，如"仅计纯代账、不含财税咨询"）——
   按用户给的口径重算一遍，再决定是留、是改、还是撤。

**实例（2026-10）**：`2026 江苏高会 · 代账公司参评 11 人 / 获评 2 人 / 18.2%`
这组数字已写入人设锚点及 40+ 副本，但按上述流程从原始 PDF 重放时
**无法复现**：通过名单 1336 人中无一家单位名称含"代理记账/代理记帐"，
含"财务/服务"类仅 9 家且多为内部财务机构；参评名单里可判定为代账/财税服务的
家数也不止 11 家（仅"智慧园财税咨询、昆山奕鑫成财税服务、无锡惠经财务咨询、
苏州众企信财务咨询、苏州德顺会计服务、徐州展鸿企业管理咨询、宿迁远拓企业管理、
江苏得源远企业管理服务、扬州邗江甑慧记账服务"就已 9 家，其中至少 4 家通过）。
→ 结论：标注"待核实"，暂停对客引用，待用户确认原口径后重算。
（全省 1999/1336/663 与整体 66.8% 可保留，这两项直接来自公告人数。）
