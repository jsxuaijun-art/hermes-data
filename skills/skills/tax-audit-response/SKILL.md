# 税务稽查应对 · 文书生成

> **协作维护**：本 skill 由 Hermes 与 WorkBuddy 双向维护，共享同一份源码。协作机制、待核验清单、变更日志见 `D:\obsidian-vault\50-Skills\exchange\`（Hermes 侧按 `HERMES-启动提示词.md` 第零步访问）。
> 分工：**方法论与案由看 Hermes，法规时效与数字看 WorkBuddy**。谁发现错谁直接改源码，改完在下方版本记录加一行。

## 这个 skill 是干什么的

面向**代理方（财税服务机构）视角**：客户被检查或稽查时，帮你完成四件事——判断处在哪个阶段、**找出本案的命门变量**、推演路径分叉、生成能直接交出去的正式文书。

服务的对象是被查企业，但使用者的立场是**协助客户依法应对**，不是替客户逃避责任。

## 总纲：稽查过关是涉税工作的标准

**一切涉税处理、账务、凭证、申报，最终以"未来能否过稽查"为标准来判断对错。** 判断一个涉税动作有没有风险，问的不是"文件允不允许"，而是"这一关过不过得了"。配合这条总纲的两点认知：
- **行政执法中没有真相，只有证据**——事实要靠证据固定，谁的证据证明力强谁占优（证据层级见 `references/03` 铁律3）。
- 企业所得税扣除看**三性**（真实性/相关性/合理性），真实不取决于有无发票、是否付款，根基于事实与证据（见 `references/04` 案由一）。

> 涉税风险是不确定但可以通过概率把控的——大多数稽查结果，取决于证据准备是否充分、定性争议是否争到位。

## 红线（任何情况下不得逾越）

1. **绝不**建议、暗示或协助隐匿、转移、销毁账簿、记账凭证及其他资料。这在《税务稽查案件办理程序规定》第27条下直接构成"逃避、拒绝或者以其他方式阻挠税务检查"，会把一个补税案升级成处罚案。
2. **绝不**编造、变造证据，不得诱导当事人作虚假陈述或订立攻守同盟。
3. **绝不**代替客户署名，不得冒充当事人或伪造授权手续。
4. **涉刑预警**——出现以下任一信号，立即提示客户聘请专业律师/税务师介入，本 skill 只处理行政程序文书：
   - 涉嫌虚开增值税专用发票
   - 逃避缴纳税款数额较大且占应纳税额百分之十以上（《刑法》第201条）
   - 检查人员明确表示拟移送公安机关
   - 案件被列为重大税务案件
5. **输出定位**：生成的是**工作底稿级的正式文本**，对外提交前必须经持证人员（税务师/律师）复核，并如实填写真实的主体信息、金额、日期。

## 工作流程

### 第 1 步：判断阶段（这一步决定一切）

先问：客户手上现在有什么文书？按表定位。

| 客户手上的文书 | 阶段 | 我方空间 |
|---|---|---|
| 只有口头通知／税管员电话 | 选案／案头分析 | 最大，可自查自纠 |
| 《税务检查通知书》 | 检查 | 大，最佳介入点 |
| 《调取账簿资料通知书》《询问通知书》 | 检查中 | 大 |
| 《税务行政处罚事项告知书》 | 审理 | 中，最后的正式答辩窗口 |
| 《税务处理决定书》《税务行政处罚决定书》 | 执行 | 小，转入救济程序 |
| 《税务稽查结论》 | 结案 | — |

阶段特征、法定时限、权利要点见 `references/01-阶段文书对照与要素清单.md`。

### 金税四期选案视角（预判"为什么被盯上"，参考，不引具体政策数字）

金税四期核心是"以数治税"——税收征管从"经验管税/以票控税"走向数据驱动。以下方向用于辅助判断客户为何被选中、预估检查重点（**仅方法参考，相关政策条文以官方现行有效版本为准**）：
- 异常指标触发（进销项不匹配、收入与成本费用偏离、长期零申报、税负率异常、发票流资金流不一致等）→ 往往对应"少计收入/虚列支出/发票风险"类案由。
- 重点关注对象通常包括：长期亏损但持续经营的、税负显著低于同行业、关联交易频繁、频繁作废/红冲发票、大额公转私、个人账户收付经营款项等。
- 对中小微客户：自身数据异常的，建议尽早自查、备齐证据，争取在选案/检查早期消解。
- ⚠️ 金税四期具体政策/功能细节更新频繁，**只借"风险画像"思路，不将任何特定政策数字作为引用依据**；引用条文一律以官方原文为准。

**不要只贴标签。** 判断完必须说清楚**这个阶段为什么值钱、错过会怎样**。例：

> 检查阶段：定性尚未锁定，还停在取证环节；站在"无票支出"案由看，这是洗清"凭证瑕疵 ≠ 偷税"的黄金期，动作慢了才被动。

**铁律：越早介入越好。**《税务处理决定书》一旦送达，复议诉讼地位断崖式下降。

### 第 2 步：采集要素（分层，按优先级）

**A 层 · 主体信息**（可边推进边补，不阻断判断）
- 纳税人全称、纳税人识别号、注册地址、法定代表人、财务负责人、联系电话
- 稽查机关全称、检查人员姓名（是否两名以上）、案号
- 涉案税种、所属期间（精确到年月）、争议金额（分税种，**注明含税／不含税**）

**B 层 · 命门变量**（见第 2.5 步，**不齐不得出文书**）
- 检查机关对该事项的**原文表述**——是只要求"说明"，还是已定性为"多列支出"／"少计收入"？**必须原文引用，不要转述**
- 涉案交易对手的现状（工商状态、履约状态）
- 客户的税收身份（是否小型微利、一般纳税人／小规模、适用税率）

**C 层 · 证据与情节**（决定能走多远）
- 可取得的证据清单（合同、银行流水、出入库单、运输单、记账凭证编号、对方证明等）
- 是否已自查补缴、补缴时间与金额、是否已缴滞纳金
- 纳税信用等级、是否首违、近五年有无同类处罚
- 客户最想要的结果（免罚 / 降罚款倍数 / 降定性 / 分期缴纳）

> **暂缓机制**：B 层要素不齐时，明确输出"**要素不齐，暂缓出文书**"，先把问题问清楚。宁可被嫌啰嗦，也不要在信息不全时替客户做假设——一个错误假设会让整份文书作废。

---

### 第 2.5 步：找命门（整个流程里最值钱的一步）

每个案子都有**一个变量**，它的两种取值通向两条完全不同的路径。找到它，集中火力先解决它。

**自问句式：哪一条信息一旦改变，整个应对策略要推翻重来？**

已识别的命门：

| 案由 | 命门变量 | 取值 A | 取值 B |
|---|---|---|---|
| 无票支出 | **对方的工商状态** | 已注销／撤销／吊销／被认定非正常户 → 28号公告第14条适格，**目标一分不补** | 仍存续只是失联 → **不适格**，转"只调增、不加罚" |
| （其余案由待补，见 `references/04`） | | | |

**输出要求**：把命门标在最前面，加 ★，并把它列为客户要办的**第一件事**（通常是一个可立即执行的核查动作，如上国家企业信用信息公示系统查对方现状并截图留证）。

> 命门往往是反直觉的。例：无票支出案里，供应商"已经注销"反而比"活着但不配合"好办得多——前者正好构成第14条的适用情形。别凭客户一句"联系不上"就下判断。

---

### 第 3 步：分析定性（六件事，顺序别乱）

对照 `references/02-法律依据速查.md`：

1. **追征期**：3年／5年（累计10万元以上）／偷税无限期。最便宜的抗辩，永远先过一遍。**不成立就明说，别让客户抱期待。**
2. **定性**：偷税（征管法63条，50%–5倍罚款）vs 少缴税（52条）vs 不进行纳税申报（64条）。**定性之争比金额之争重要十倍**——定性决定罚款倍数和追征期。核心论证方向始终是"降定性"。
3. **程序瑕疵**：执法主体资格、两名以上检查人员、调取账簿的审批层级与退还期限、询问笔录形式要件、告知义务、听证权、办案期限。**这是底牌，见下方使用纪律。**
4. **从轻/减轻/不予处罚抓手**：主动自查补缴、配合检查、首违不罚清单、《行政处罚法》第33条、华东区域裁量基准的裁量阶次。
5. **先查案由**：`references/04-常见案由论证要点.md` 里已有的案由，按其论证顺序走。**程序性补救 → 定性抗辩 → 金额测算，顺序不能跳。**
6. **双文书拆分**：《税务处理决定书》＝补税＋滞纳金，属纳税争议，复议有清税前置；《税务行政处罚决定书》＝罚款，**非纳税争议，可单独复议/起诉，无清税前置**。税款撼不动时，罚款是独立战场。

**程序瑕疵的使用纪律（重要）**：
检查和审理阶段**不主动抛出**程序抗辩，留作底牌。一旦提前打出来，税务机关有时间补正，且会把案件推向对抗。只有在下列时机才出手：① 拟处罚明显过重需要谈判筹码；② 进入听证、复议阶段；③ 决定正面争议时。
平时只做一件事：**按 `references/01` 的清单逐条留痕存档，编好证据编号。**

---

### 第 3.5 步：路径分叉推演

命门变量有几种可能取值，就列几条路径。**每条写清楚：适用条件 → 目标 → 具体动作 → 兜底方案。**

| 情形 | 路径依据 | 目标 | 兜底 |
|---|---|---|---|
| {{取值A}} | {{法条}} | {{理想结果}} | {{退守到哪}} |
| {{取值B}} | {{法条}} | {{次优结果}} | {{退守到哪}} |

**不要在信息不全时只给一条路**——那等于替客户做了假设。宁可给两张地图，也不要给一条可能错的路。

## 输出格式

### 案情分析阶段（还没到写文书时）按六段输出

1. **阶段判断** + 这个阶段为什么重要 / 错过会怎样
2. **命门 ★** + 需要客户立刻去办的第一件事
3. **待补要素**（按 A/B/C 分层，标明哪些必须补、哪些可后补）
4. **路径分叉推演表**
5. **测算区间**（至少两档，标明口径、起算日、天数；罚款区间一并给出）
6. **下一步动作**（按优先级排序，不要平铺）

### 测算纪律

- 至少给**两档**（不同税收身份／不同定性）
- 滞纳金给**区间**，标明起算日和计算天数
- 罚款按 **0.5–5 倍**给区间
- **严禁默认 25%**——先确认是否小型微利
- **测算只是兜底**。程序性补救走得通的话，整张测算表都用不上。**别让数字把注意力从主打路径上带走。**

### 文书阶段

- 直接输出可复制的完整文书正文，**不要用代码块包裹**（方便直接粘进 Word）
- 待客户确认或补充的内容统一标 `【待确认：xxx】`，不要自己编
- 附件清单单独列在文末
- 文书之后另起一段**给客户的内部提示**（不进正文）：风险点、可争取空间、下一步动作

## 案例积累

每办完一个案子，按 `cases/_案例模板.md` 的格式存一条脱敏记录。案例库是这个 skill 越用越值钱的唯一来源，也是它区别于通用知识的核心资产。详见 `cases/README.md`。
