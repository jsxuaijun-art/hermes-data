# 取数请求处理规范 (Scraping-Request-Handling)

> 本 skill 是"行为层"：管怎么接需求、怎么交付、强反爬怎么决策。
> 工具/环境技术细节在 scraping-dispatch 与 python-web-scraping-setup（均为手动创建，无法被 curator patch，故行为规范独立存放于此）。

## 交互契约（用户 2026-08-04 明示，最高优先级）
用户只给一句话需求（如"我要抓XX的数据"），**绝不点名工具、绝不指挥过程、绝不给技术细节**。
- agent 必须：按难度分层自动选工具 → 执行 → 验证 → 直接交付结果
- 禁止：向用户解释用了什么工具、报告中间过程、请示工具选型
- 交付物 = 数据/结果，不是过程叙述
- 用户是财税行业老板，非技术背景：技术表述零输出，只输出结论
- 用户原话："我不要过程，只要结果" —— 拿不下时诚实说"这块我拿不下"+给替代方案，不硬编假数据

## 难度分层调度（每层对应 scraping-dispatch 的决策树）
| 难度 | 场景 | 动作 |
|------|------|------|
| 简单 | 静态HTML/开放API | 轻量工具直接抓，不请示 |
| 中等 | JS渲染/需登录 | 浏览器级工具，自动上 |
| 强反爬 | 有签名/验证码/IP信誉 | 按反爬阶梯逐级试，全败→方案B |
| 物理墙 | 抖音/小红书类 IP信誉墙 | 直接走替代路线，不硬磕（见下） |

## 强反爬平台（抖音/小红书）政策 —— 用户已拍板
不搞"改网络身份"硬爬。取数一律走：蝉妈妈/新抖/飞瓜、巨量算数、抖音开放平台OAuth、方案B手机手动采集。
完整分析（网络身份四层模型+方案盘点+合规理由）见 `references/strong-anti-bot-routes.md`。

## 需求类型：实体/品牌全网提及审计（两个变体，先判类再动手）

母类共性是：**不是**抓某一个站，而是**跨站枚举 → 逐条点名验证 → 分类交付**。
但两个变体的交付物完全不同，**接需求第一件事是判类**：

| 变体 | 触发 | 交付 | 参考 |
|---|---|---|---|
| **A. 负面舆情排查** | "列出所有提及'苏州盈信'的网站/社交媒体，尤其是有负面评价的"（2026-10-13 定型） | 三色 xlsx（负红/正绿/混淆黄）+ md | `references/brand-mention-audit.md` |
| **B. 活动/事件「是否真存在」核实** | "查找如下要素：'<主体>'、'<人名>'，沙龙/政策宣讲，我记忆中是在<某地>的活动"（2026-10-14 定型） | 证据链 md（结论/一手来源/同期活动对照/覆盖边界），**不是分类清单** | `references/entity-event-mention-verification.md` |

变体 B 的核心差别：用户是**在核实自己的记忆**，所以①关键词要按「主体×人物×形式×地域×时间」笛卡尔式铺（**"形式词"必须全铺**——沙龙/宣讲/讲座/专题辅导/分享会叫法各异，只搜"沙龙"会漏掉真实那场）；②**必须显式纠正用户记忆偏差**（本次实况：用户记"相城区高新区"，实为"相城区太平街道"，且区政府官网并未发布）；③拿到主办方后**反查同场其他主讲人/协办方**做第三方交叉印证；④同期同类活动单列对照表防张冠李戴。

### 变体 A 要点（七条）

1. **用 `site:<域名>` 铺平台矩阵，不要只搜品牌词。** 每个平台都查一遍，没查过才敢写"未命中"：
   通用搜索（品牌词精确 `"苏州盈信"`）× 企业库（企查查/天眼查/爱企查）× 政府与行业公示（学会/财政局/政务网/裁判文书/行政处罚）× 招聘（BOSS直聘/前程无忧/58/垂直人才网）× 社交（`site:douyin.com`、`site:xiaohongshu.com`、`site:weibo.com`、`site:zhihu.com`、`site:bilibili.com`）× 点评投诉（大众点评/高德/黑猫）。
2. **所有查询丢进一个 `execute_code` 里循环调 `web_search`**（一次 8–10 条），比一条一条发工具调用省一半以上往返；命中候选页再用 `web_extract` 拉正文。
3. **抓完必做"点名正则校验"**：`len(re.findall("<品牌名>", content))` 为 0 就是没提，直接丢掉，别靠标题/摘要猜。**搜索摘要命中 ≠ 正文命中**——实测多篇竞品"苏州代账公司排名"软文根本没写盈信。
4. **查不到 ≠ 不存在（覆盖边界要如实写）**：百度在无头浏览器下会跳图形验证码（`wappass.baidu.com/static/captcha`），抖音/小红书/大众点评/黑猫需登录态。碰到就**换后端（通用搜索/Bing）或改用 `site:` 枚举**，并在交付里注明"哪些平台未能穷尽、为什么"。这是诚实边界，不是失败；但不写就是误导。
5. **交付形态**：分类清单（负面/正面/中性/同名混淆）+ 每行一条可点链接 + 负面内容**逐句摘录原文**（不推断、不改写、不失实）+ 按急迫度给动作建议。落成三色 xlsx（负红/正绿/混淆黄）+ md 说明，按打包铁律 folder→zip，桌面只留压缩包。
6. **竞品 AI 黑稿识别 —— 本类需求的高价值产出。** 见到"XX地区代账公司深度评测报告"这类稿，核四条签名：①署名/来源自认 AI（如"AI招财兔数字员工"）；②对比对象含作者自有品牌；③"第三方数据"无出处；④同一稿件多落点发布。命中即认定为竞品对比软文，且**这类稿往往带硬伤事实（成立年份、许可证号、门店数），拿到就是澄清文/平台投诉/律师函的抓手**。
7. **三类必须单列、不能混进普通条目**：`a.` 政府/行业官网公示（杀伤力最大，客户一搜就看见，必须提醒用户立即内部核实）；`b.` 冒用/搭便车（第三方站在页脚植入品牌名做讨债/催收等 SEO，污染搜索结果）；`c.` 同名不同主体（稀释品牌辨识度，与本公司无股权关系）。

完整查询矩阵、黑稿签名清单、交付模板与工作实例见 `references/brand-mention-audit.md`。

### 变体 B 要点（六条）

1. **判类**：用户说"我记忆中有一场…帮我找找"，是核实不是舆情排查 → 交付证据链 md，**不要套三色 xlsx**。
2. **组合面铺词**：主体全称/简称 × 人物 × **形式词（沙龙/宣讲/讲座/专题辅导/分享会/圆桌会/公开课 全铺）** × 地域（区/街道/园区/开发区 全铺） × 时间；全部丢进一个 `execute_code` 循环 `web_search`。
3. **一手来源优先**：主办/承办单位官网 > 企业官网页（含现场图）> 本地权威媒体（名城苏州 2500sz 系等）> 同场他人侧记。拉到正文必须**点名核验**文章里真有那两个要素。
4. **必须显式纠正记忆偏差**：用户的"某区某街道/园区"是提示不是约束；本次实况是用户记"相城区高新区"、实为"相城区太平街道"，且区政府官网未发布。把"你记的是 A，实际是 B，同一场活动"写进结论——这是本类交付最高价值的一句。
5. **交叉印证靠同场其他人**：拿到主办方/活动名后反查同场主讲律师、协办单位的署名稿，常能补出企业自家稿没写的细节（本次补出确切地点与参会 30 家）并拿到独立第三方口径。
6. **同期活动单列对照表** + **覆盖边界如实写**（公众号图文不进通用索引、视频号完全封闭、抖音站内搜索受限只能枚举账号矩阵）。

**公众号/微信图文维度 —— 唯一外部入口是搜狗微信**（用 `execute_code` 跑本 skill 的 `scripts/sogou_wx_search.py <关键词> [数量]`，输出公众号名/标题/日期/还原后的真实 mp.weixin.qq.com 链接）：
- 微信图文对通用引擎（含 `site:mp.weixin.qq.com`）不可见，只有搜狗微信抽样收录，是唯一能拿到公众号文章链接的外部通道。
- **不要用 wechat-article-search 技能的 node 版 `search_wechat.js`——其实测解析器失效，静默恒返回 total:0**，会白白浪费时间；直接跑上面的 Python 版。
- 三个固有边界，交付时讲清楚：①搜狗只是抽样收录，搜不到 ≠ 那篇文章不存在；②**图片内的文字不进索引**（验证图片内容要抓图后 OCR/视觉模型读图，Windows 桌面另说）；③还原的 mp.weixin.qq.com 是带时效的签名链接，过期就让用户在微信里按公众号名直接搜。
- 限流纪律：每批查询间 sleep 3–6s；连发会被封到连基准词都返回 0；一个关键词零命中先换近义措辞再判"无"。
- 用户要"换用其他模型/其他路径找公众号"：这就是那条"其他路径"——不走通用 web_search，直接打搜狗微信通道。

完整六步方法论、交付结构与工作实例见 `references/entity-event-mention-verification.md`。
