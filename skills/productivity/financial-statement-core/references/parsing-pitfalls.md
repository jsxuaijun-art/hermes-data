# 读表 parsing-pitfalls（已踩坑清单）

本文件汇总财务报表读取层的所有已知坑与处理口径。改动 fs_reader.py 前先读这里，
避免重新踩。来源：company-deregistration/qingshui_risk_engine 实盘（2026 苏州 QD 案例等）。

## 1. 期初 vs 期末（最危险，差一个数量级）
- 常见科目余额表表头是「期初余额|本期发生额|本年累计发生额|期末余额」多组借贷子行
  （如 R5: `借方|贷方 借方|贷方 借方|贷方 借方|贷方`）。
- 若取**第一组借贷列=期初**，会把期初值当期末诊断，严重失真
  （真实案例：应收 496 万被读成应收/应付/货币一整套期初值，资产总计从 74.68 万 记成 585 万）。
- **口径**：期末 = 最后一组「借方/贷方」（覆盖式取尾）；第一组 = 期初。

## 2. 资产负债表左右双栏
- 布局：左[A名称|B行次|C期末|D年初]、右[E负债名|F行次|G期末|H年初]。
- **必须读 C 列和 G 列（期末）**。「取最后非零数字列」会取到 H（年初）——这是真实炸过
  的坑（客户实盘文件）。
- 右栏行常因左 A 列为空（负债段往下排）而被误跳过 —— 左栏、右栏必须分开处理。

## 3. 现金流量表 sheet 误匹配
- 现金流量表行名会误匹雷区/风险关键词（如「销售产成品收到的现金」命中「存货」、
  「支付其他与经营活动有关的现金」命中「货币资金」）。
- **口径**：凡 sheet 名含「现金流量表」一律跳过，且不计入统计。

## 4. 科目余额表双层合并表头
- R4 合并表头是「科目编码|科目名称|期初余额|本期发生额|本年累计|期末余额」，
  R5 才是 `借方|贷方×5` 子行。借贷列必须从**子行 R5** 识别（表头行本身无「借方/贷方」）。
- 科目名称/编码列从 R4（合并表头的顶格单元）取；数据从 R6 起。
- `_find_header_row` 会误中标题行（如第一行就是「科目余额表」四个字，含「科目」+「余额」）。
  → 优先找含「科目名称/科目编码」**且其后行出现「借方/贷方」子行**的行。

## 5. 「库存」关键词坑
- 存货雷区若含裸关键词「库存」，会把「库存现金」匹配进来导致存货误报。
- **口径**：存货关键词用 `存货/库存商品/原材料/在产品/生产成本/产成品`（去掉裸「库存」）。

## 6. xls 老格式
- 会计软件导出的 .xls 需用 `xlrd`（openpyxl 读不了 xls），且是双栏多 sheet。
- WSL 访问 Windows 报表路径：`D:\...\Desktop\` → `/mnt/d/...`。

## 7. 数据源优先级（消费方注意）
- 科目余额表（单元格明细）比报表行的汇总数更细、更权威，应**覆盖**报表（如应付账款明细差）。
- 但**清税/净资产测算**要用报表权威总额（`totals`），因为余额表明细借贷净额 ≠ 报表总额
  （存在暂估/预付冲抵）。两者用途不同，别混。

## 8. 合计/总计行
- 科目余额表末行的「合计/总计」要跳过，不进 detail。

## 9. 合并单元格写入
- openpyxl 对已合并单元格的非顶格单元写值会报 `MergedCell object attribute 'value' is read-only`。
  生成测试样本时，先写值再合并，或避免向合并区非顶格写值。
