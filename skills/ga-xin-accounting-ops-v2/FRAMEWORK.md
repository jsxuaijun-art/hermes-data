# v2 框架说明书：CARE（实例—规则—引擎—回归）

> 本文件是**接手智能体**读完移植包 `README_给智能体.md` / `MANIFEST.json` / 源书 OCR 语料后，独立提出的重构方案与落地结果。
> 对照基线：`ga-xin-accounting-ops` v1（2026-11-18，19 文件）。本技能为 **v2 实验性重构**，与 v1 并列，不覆盖、不软链到 `~/.workbuddy/skills/`。

---

## 1. 一句话

v1 是「按场景翻哪个文件」的**文档查表**；v2 改成「**一个客户实例进 → 一次全链可复算的结论出 → 评估集守住口径不退化**」的**可计算内核**。

**CARE 四层**：

| 层 | 目录 | 解决 v1 的什么 |
|---|---|---|
| **C**ase 客户实例 | `schema/` | 5.2 无实例、无法跨会话续做、无法三年滚动 |
| **A**ctive Rules 显式规则 | `rules/rules.json` | 5.3 口径是散文、5.4 政策无生效期 |
| **R**ecalc Engine 单入口引擎 | `engine/rnd_engine.py` | 5.5 八个命令孤立、5.1 多条件无裁决顺序 |
| **E**valuation 回归护栏 | `tests/` | 5.10 没有评估集、无法证明"更好" |

横切调度层：`workflow/state_machine.md`（状态 + 迁移条件 + 裁决顺序，替代线性 S0–S7）。
知识层：`references/` 与 `assets/` **原样保留 v1 全部 17 个文件**，降级为「依据层」——规则表每条都指向它们，但不参与运行时计算。

## 2. 选型理由（为什么不照抄 §6 的五个方案全做）

移植包建议组合是 `E 打底 → B 口径显式化 → A 承载状态 → D 输出交付物`。我采纳前三，**明确不做 C 与 D**，理由：

1. **先 E**：v1 连"新框架是否更好"都无法判断。没有判据的重构只是换排版。所以第一件事是把源书**例 4-1** 做成黄金案例——它有完整、可复算、有政策文号支撑的数字链（限额 294,444.44 → 40 行 3,744,444.44 → 加计基数 2,801,984.12）。
2. **再 B**：本领域的头号事故是**口径用错**（20% vs 10%、两套账、分档依据、40 行是否重复乘 80%）。把 12 条硬内核写成带 `effective_from / effective_to / priority / scope / authority` 的规则条目，机器才能替人守住口径。**规则显式化优先于流程美化**。
3. **再 A**：规则必须作用于对象。没有 `ClientCase`，"既是高企又是集成电路又亏损又有委托境外又逢复审年"这类交叉客户只能靠人拼文档。
4. **不做 C（证据链优先）**：需要真实客户证据样本才能验证，手上只有一本书。但把 `evidence` 字段与 `evidence_gaps` 输出做进实例与引擎，**留了接口**。
5. **不做 D（交付流水线）**：依赖真实客户参数与签收状态，且 `accounting_tax_diff.md` 汇缴主线本身待 #4 冯秀娟书。只在状态机里预留 `DELIVER` 状态的产出物契约。
6. **5.9 单源书 / 无政策原文在线核验：无解**，如实保留。规则表的 `authority` 字段只记文号，不假装已联网核验。

### 代价（诚实）

- 规则表 + 实例 schema 有**维护成本**：政策变更要人审规则条目，比改一段散文重。
- 出现**双轨**：依据层（references）与可执行层（rules）可能不同步。缓解：每条规则强制带 `source`（书页码）与 `authority`（文号），评估集含一致性断言。
- 引擎是**命名算子 + 数据驱动**，不是通用 DSL/规则语言：新增规则若需要新算子，仍要改 Python。这是刻意收敛，避免为了"框架感"引入 YAML/表达式引擎依赖。
- 运行时仍是 Python 3 标准库、零第三方依赖；没有引入数据库，实例是 JSON 文件。

## 3. 关键机制

### 3.1 规则的三道护栏

| 机制 | 字段 | 效果 |
|---|---|---|
| **生效期** | `effective_from` / `effective_to` + 引擎 `as_of` | `as_of=2028` 时 2023年第44号 120% 规则自动失效，回落 100%（v1 只写在 TODO 里） |
| **裁决顺序** | `priority` 降序 + `scope` | 多条件交叉时先算准入与负面清单，再算归集口径，最后算优惠与风险；冲突时高优先级覆盖并记录 `trace` |
| **口径防混** | `scope`（加计扣除 / 高企认定 / 双口径 / 通用）+ `conflicts_with` | 房屋折旧、装备调试费、知识产权摊销、其他费用 20% vs 10% 显式标注为互斥口径，引擎输出 `cross_scope_warnings` |

### 3.2 全链可追溯

引擎输出 `trace`：每个结论带 `rule_id / op / inputs / output / source / authority`。8 维里的「可追溯」从"文档里有人写了页码"升级为"每个数字能机器回溯到规则与文号"。

### 3.3 状态机裁决（替代 S0–S7 查表）

`INTAKE → EVIDENCE → SETUP → COLLECT → CALC → FILE → REVIEW → DELIVER`，每个状态有 `entry_condition / required_evidence / outputs / next / on_fail`。多条件交叉不再靠人判断先翻哪份文档，而是按状态机逐状态过闸。

### 3.4 政策时效核验（新增，每个财税 skill 必备）

`rules/rules.json` 每条规则已带 `authority`（文号）+ `effective_from/to`（生效期），因此**机器能自动生成"待核文号清单"**：`python engine/rnd_engine.py verify` 抽取全部引用文号，按「已到期 / 90天临期 / 现行（有期）/ 现行（无期）」分类，并为每个文号给出官方核验信源（税务总局 fgk.chinatax.gov.cn / 财政部 / 科技部 / 电子税务局表样）。引擎自身零依赖联网，联网核验动作交由 `cn-regulation-verification`（fgk 状态标签终裁）与 `tax-regulation-monitor`（定期巡查）执行。作业纪律：引用前必核、已修改≠废止按现行条款引、到期规则改 effective_to 不删除、涉及税率/比例/金额/文号回查官方原文。

## 6. 独立复核发现（回源书语料，不靠二次总结）

按移植包 §8 第 4 步，从 `source_corpus/book_core.txt` 独立复核：

1. **p109** 明确「自 2021 年度起……改为统一计算全部研发项目『其他相关费用』限额」，并说明 97 号逐项目口径已废 → 硬内核 #1 成立。
2. **p297** 原文「**最近一年**销售收入小于 5000 万元（含）……不低于 5%；5000 万至 2 亿（含）4%；2 亿以上 3%」→ 硬内核 #2 成立，v1 的更正是必要的。
3. **p323**「应按照《企业年度研究开发费用结构明细表》设置高新技术企业认定**专用**研究开发费用辅助核算账目」「由具有资质的中介机构专项审计」→ 硬内核 #4 成立。
4. **p234** 表 5-6 行次：34 = 经限额调整后的其他相关费用；35 = 二、委托研发（36+37+39）；36 委托境内；37 委托境外；**38 = 其中允许加计扣除的委托境外费用**。故 `40 = 2 + 36×80% + 38`，38 已是限额后数，不再乘 80% → 硬内核 #8 成立。
5. **p204** 文字解析给出例 4-1 完整数字链：**(1,700,000+950,000+0)×10%/(1−10%) = 294,444.44**；A 分摊 252,380.95、B 分摊 42,063.49；委托境内 560,000、境外 240,000；年度小计 3,744,444.44；费用化 2,752,380.95 + 本年摊销 49,603.17 = **2,801,984.12**。
6. ⚠️ **表格页 p201–203 / p205 的 OCR 数字确实倒置乱码**（如 `000 008`），验证了语料 README 的警告。因此 golden case **只采信文字解析页 p204 / p206**，表格页数字一律不入库。
7. ⚠️ p204 疑有原书笔误：「B 项目……第 7.2 列填写 252380.95 元」，按同页分摊公式应为 **42,063.49**。v2 采用可复算的公式结果，并在规则 `note` 中标注，不照抄该句。

## 7. 维护纪律（继承 v1 并加严）

- 裁决顺序：**现行政策原文 > 源书 > OCR 文本 > 规则表 > 引擎输出**。规则表是「已审核的政策快照」，不是政策本身。
- 新增/修改规则必须同时：填 `authority` + `source` + `effective_from`、加一条 golden case、跑 `run_tests.py` 全绿。
- 涉及税率、比例、金额、文号，回查官方原文或原 PDF 页面图像；表格页 OCR 数字不得直接采信。
- 每年复核政策版本（44 号 120% 2027 到期、申报表版本）；到期规则改 `effective_to`，**不要删除**（保留沿革）。
- 依据层 `references/` 保持 v1 原样；如需修订，同步回填 v1 与规则表 `source`，避免双轨漂移。
- 内部作业参考，不构成税务意见；实际申报以电子税务局当年表样与主管税务机关口径为准。
