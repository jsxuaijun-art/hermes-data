# 财税/计算类书籍蒸馏：扫描 OCR 与验证纪律

适用：拆的源书是扫描版/OCR 文本，且要建成「数字链可复算」的 skill（税法、账务、
定价、申报表填报等不可出错的 domain）。

## 扫描版 OCR 的表格页陷阱

- 表格页（资产负债表、申报表行次、明细表）OCR 数字经常**倒置/乱码**（实测源书某
  表页出现 `000 008` 这种），务必以**文字解析页**的数字为准；表格页数字一律不入
  golden case。
- 采信一个数字前先追问：来源是文字段还是表格行？跨页对不上时查原 PDF 页面图像，
  不采信 OCR 中间产物。
- 书中个别数字疑似**原书笔误**（公式算出的值与正文引的数值矛盾）：采用可复算的
  公式结果，并在规则/注记中标明，不照抄原句。

## golden case 的三条纪律

1. **重推导，不照抄结论**：从源文工作示例的输入（分项金额、比例、时间）重新算出
   期望值；照抄书尾数字 = 自欺（引擎哪怕错误读入都会「通过」）。
2. **数字链完整才算黄金案例**：一个示例要有完整可复算链（如 限额 → 各项目分摊
   → 行次小计 → 加计基数 → 最终行），且政策文号可引。
3. **首次跑挂是评估集在证明自己**：评估集建好第一次跑就抓出 2-3 个真实缺陷是
   正常且值得的——修规则/算子，不要为省事删断言或放宽格式。

## 政策时效：生效期建模而非 TODO

- 规则条目带 `effective_from / effective_to` + 引擎 `as_of` 参数，按 as_of 过滤
  当前生效规则——到期（如优惠 120% 满 5 年）自动回落基础档，而不是在文档里写
  「待办提醒」。
- 到期规则**改 `effective_to`，不删除**（保留沿革）；早期年份的回放案例依赖旧规则
  （如 2019 年命中逐项目口径）。
- 改一条规则 = 三件事一起做：填 `authority`（文号）+ `source`（源书页码）+
  `effective_from/to`；加/改一条覆盖它的 golden case；跑回归全绿。规则表是
  「已审核的政策快照」，不是政策本身——涉及税率/比例/金额/文号必须回官方原文核。
