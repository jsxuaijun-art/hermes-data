# L6 并行调研 · 执行手册（2026-08-02 实测跑通）

## 触发场景（用户原话模板）
- 「帮我同时调研：A、B、C这三个方向」→ 3路并行
- 「这次调研5个方向」→ 需先把并发调高再并行
- 「调研一下XX，给份报告」→ 单路深挖
- 「并行调研完给我出个对比表」→ 并行完汇总成对比文档

## 并发配置
- 当前 `max_concurrent_children: 3`（`~/.hermes/config.yaml` delegation 段）
- 用户明确：以后要增加到 5。改法：config.yaml `delegation.max_concurrent_children: 5` + `max_async_children: 5`。
- 3 个是性价比最优：耗时最短、结果够全、成本可控。>5 成本上去、质量稀释，不建议。
- batch 模式一次最多 3 个任务（受 max_concurrent_children 限制）；要更多就分两批（3+3）。

## 派单要点（实测经验）
1. **每个 goal 必须自包含**：子智能体没有父会话记忆，要把"调研主体是谁（苏州盈信：高级会计师创办16年/苏州上海覆盖/唯一以代账公司名义通过高会评审）+ 要什么 + 输出格式 + 中文输出要求"全写进 goal/context。
2. **明确要求中文输出**：不写则子智能体默认英文，污染最终报告。
3. **输出格式给足结构**：指定标题前缀（如【方向A-...】）+ 表格 + 可执行建议，否则子智能体自由发挥。
4. **网络受限兜底**：子智能体可能被 Bing 污染/无法抓取，明确允许"基于行业公开常识给结构化判断并标注'推断'"——比干等搜索强。
5. **落盘路径**：子智能体报告会写到各自 session 的工作目录（如 /home/dmin/xxx.md），不一定在桌面。父会话要用 read_file 读回来，再汇总成桌面 docx。
6. **合并交付**：多方向报告合并成一个 docx 放桌面（符合用户"只出docx放桌面"硬偏好），命名带日期如 `L6并行调研_三方向综合报告_20260802.docx`。
