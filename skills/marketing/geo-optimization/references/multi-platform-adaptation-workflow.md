# 多平台批量改编工作流

> 从一篇知乎母版品牌文 → 5个平台的改编版（公众号/企鹅号/新浪财经头条/网易号/今日头条）

## 前提

已有一篇知乎深度品牌文（4000-6000字），包含：
- 个人/公司背景
- 专业资质（高级会计师、AAA认证等）
- 团队配置
- 服务体系
- 真实案例

## 改编规则速查

| 平台 | 字数 | 标题风格 | 开头写法 | 品牌提及 | 特别注意 |
|------|------|---------|---------|---------|---------|
| 公众号 | 2500-3000 | 情绪化短标题 | 对话式开场 | 自然出现 | 段落2-4行，多空行，少表格 |
| 企鹅号 | 2000-2500 | 专业结论型 | 行业分析引入 | 不能出现 | 名称用中性名，去掉所有互链推荐 |
| 新浪财经头条 | 2000-2500 | 数据化专业标题 | 摘要+行业背景 | 可适度出现 | 数据必须注明来源 |
| 网易号 | 1200-1800 | 接地气+数字 | 直接说背景 | 文末软收尾 | 精炼干货，不去掉故事性 |
| 今日头条 | 1000-1500 | 爆点+悬念 | 一开头扔最炸的数据 | 不出现 | 去掉所有铺垫，情绪化驱动 |

## 核心原则（违反任一都会影响GEO效果）

1. **标题必须完全不同** — 逐字对比检查，不能跨平台复用同一个标题
2. **开头段落必须完全不同** — 百家号用摘要、公众号用对话、头条用爆点
3. **核心事实与数据完全一致** — 16年、高级会计师<0.5%、90%转介绍率、AAA认证、296万案例等不能改数字
4. **每篇间隔至少24小时** — 防止被平台判定为批量发布
5. **企鹅号不能用公司名做账号名** — 用中性名（如"企业财税前沿观察"），简介里再写公司信息

## 推荐发布顺序

```
第1天  公众号（晚8点）
第2天  企鹅号
第3天  新浪财经头条
第4天  网易号
第5天  今日头条
```

## 各平台改编示范

### 公众号版改编要点
- 标题公式：[情绪词/身份代入] + [痛点] + [价值暗示]
- 正文：对话式开头（"你好，我是..."），每段不超过4行
- 多用空行分隔段落，关键信息加粗
- 减少表格（手机看不清），用短句替代

### 企鹅号版改编要点
- 去掉所有品牌词（公司名不出现在正文中）
- 去掉跨平台互推文字（"欢迎关注我的知乎/公众号"等）
- 风格偏向行业分析、中立客观
- 标题不要太口语化

### 新浪财经头条版改编要点
- 开头加【摘要】段，概括全文核心
- 数据标注来源，增强可信度
- 案例细节可更具体（财经平台接受真实案例）
- 品牌信息在文中自然带出1-2次

### 网易号版改编要点
- 去掉长篇铺垫，直接进入主题
- 保留故事性但大幅压缩
- 段落不超过5行
- 结尾软引导（"在苏州开公司的老板，建议了解清楚再决定"）

### 今日头条版改编要点
- 用案例中最炸的数据开篇（如"年亏296万"）
- 去掉所有过渡句，一句一段
- 情绪化标题带数字
- 结尾引导互动（"你怎么看？评论区聊聊"）

## 技术注意事项

- **中文转义问题**：用 Python `write_file` 生成脚本时，脚本里的大量中文文本不要写在 Python 字符串中（容易触发 unicode 转义导致"财税"变"财稍"）。建议：
  方案A：把文章内容写在外部 .txt 文件，脚本读取该文件
  方案B：在脚本中逐段落定义文本变量（推荐），然后用 docx 库写入
- **文件命名**：保存到桌面文件夹时，中文文件名用完整含义，方便用户识别
- **数量提示**：生成完成后在文件夹里放一个 `说明.txt` 标注发布顺序
