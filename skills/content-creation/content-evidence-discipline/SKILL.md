# 内容有依据纪律（讲话必须有依据）

## When to Use

- 任何创作内容（短视频文案/公众号文章/客户答复/政策解读/测算结论）涉及政策、数据、法规、文号、日期、数字时
- 用户问"这句话依据是什么""这个数字哪来的""敢不敢保证没编"
- 城市破播/苏州政策素材写成文案之前（素材来自监控，监控给的是线索不是事实）
- 换电脑、新员工/AI 接入、需要向客户承诺数据准确性时

## 定位

盈信企业管理（苏州）的公司级纪律，2026-09-21 由徐总签发：**讲出去的每一句话必须有可查证的真实依据；没有依据→不说；有一分依据→说一分。** 本 skill 是纪律的可执行版本（如何核实、如何判定、交付要带什么）。纪律文件全文：桌面 `盈信-AI内容纪律文件.txt`、Obsidian `公司运营/AI内容纪律-讲话必须有依据.md`。

## 四条铁律

1. **严禁 AI 幻觉（零容忍）**：禁止凭空臆断、编造数据/政策/人名/文号/日期/事件。平台审核红线、客户信任，一次捏造就归零。宁可少说，绝不瞎编。
2. **不确定，就不写**：吃不准的政策/数据不写进内容，或标注"以官网最新为准"。引用必须有出处（官方文号/政府官网链接/权威媒体）。
3. **先核实，再引用（次序不可颠倒）**：检索原文→逐字核对→确认成立→才写进文案。禁止"先引用未核实"。**哪怕结论事后证明正确，只要次序是先引用后核实，即算违规。**
4. **写事实，不写判断**：事实必须有据；观点必须标注是"看法"；不得把预测/推测包装成既定事实。

## 判定四问（每句话都要过）

1. 这句话的出处是什么？（文号/官网/权威媒体，必须答得出）
2. 我是否真的打开并核对了原文，还是只看到标题/摘要？
3. 如果没有依据，我为什么写了出来？
4. 若被客户逐字核对，能不能站住？

四问有一个答不上 → 删掉这句话，或先去核实。

## 核实四步（政策/法规类，写进文案前必须走完）

1. `anysearch` CLI 搜「<条例/政策名> + 人大常委会 + 通过/施行」拿官方链路（政务网《说明》、批准新闻）：
   ```bash
   python3 ~/.hermes/skills/anysearch/scripts/anysearch_cli.py batch_search --queries '[{"query":"苏州市低空经济促进条例 人大常委会 通过 施行","max_results":6}]'
   ```
2. `web_extract` 拉**正文** URL，逐字核对编号/日期/数字/范围/适用主体。
3. **多源交叉**：政府正文 + 政府《说明》 + 省委新闻网/人民网/司法部等权威第三方（两三个独立来源互相印证）。
4. 能答出「哪个官方源、什么时间、什么文号」才允许写。交付文案附**依据清单**：每条关键结论 → 出处 + URL + 核验日期。

## 表述纪律

用精确事实，不用模糊断言。正反示例（低空条例）：

- ❌ "苏州把低空经济写进条例了——这是立法层面的事。"（依据仅标题+URL，未核正文即断言，次序违规）
- ✅ "《苏州市低空经济促进条例》经市十七届人大常委会通过（2025-06-25）、省人大常委会批准（2025-07-30），已于2025-10-01施行。"（多源核实后成文）

## 交付要求（铁律 5，对 AI）

1. 创作前先检索官方/权威来源核实关键事实
2. 引用政策必带文号/来源/日期
3. 拿不准就明说"此条未核实，需人工确认"——绝不用专业措辞掩盖不确定
4. 交付文件附"依据清单"（每条结论出处+URL+核验时间）
5. 被指出没依据时，如实承认并立即核实/纠正，不狡辩

## 占位纪律：允许的"编造"只有一种形态（2026-10，PPT 事件后补）

徐总原话：**"为了结构的合理与完美，你可以先'编造'放在那里，但你要注意提醒我按照真实的情况修改。"**

无依据的内容**只允许以"显式占位"形态存在**，三条同时满足才算合规，缺一条就是幻觉违规：

1. **长得像占位**：文件里落成醒目标记（红色字/虚线框/「【待填】」「⚠ 待核实」），不能写成正常正文的样子——否则几天后连 AI 自己都分不清哪句是编的，用户更没法批量替换。
2. **交付时点名**：交付消息里**逐条列出**"以下是我编的/未核实的，必须替换"，并写清要填什么、去哪里取（学历→院校/专业/届别；评审数据→省财政厅公示，附年份+文号）。
3. **不许被当结论用**：占位内容不得进入对外稿件（公众号/短视频/给客户的文件），只存在于"内部待完善的初稿"。

**新增第4条（2026-10-16 企微签名素材实测）：自己写错 ≠ 待核实。** 占位只留给"AI 真的不知道答案"的事实。若写稿时发现某处其实是你已知的信息（公司所在地=苏州/双城、成立年份、团队构成、资质口径），手滑写错 → **当场改正**，不要给它打「待核实/待核对」标再推给用户——那是把"一个确定的错误"伪装成"一个待定的不确定项"，用户还得替你审一遍，比直接漏写更伤信任。判定一句话：**这处事实我到底知不知道正确答案？知道→改；不知道→才允许显式占位 + 交付点名的双条件。**（本次曾把"十七年湖北财税"当待核对项交付，实际终点是苏州/双城——已当场改正，不该让用户来兜这个底。）

**连带必做动作（本次事件的核心教训）**：被用户点名一处编造时，**不要只改那一处**——立刻对整份交付物做一次**事实性内容普查**，把 AI 自填的院校/届别/年份/人数/通过率/排名/客户数/"N年经验"全部揪出来统一处置。本次一份公司介绍 PPT 里 AI 编了 **6 处**（专业背景院校、参评/获评人数、通过率 18%、同业对比 74.6%、"25年经验"、"1000+客户/90%转介绍"），用户只发现了 1 处；只修被点到的，剩下 5 处会继续冒充事实。

**普查方法**：直接扫生成脚本（build.js / docx 生成器）里的字符串常量，按"专有名词+数字"筛：院校名、年份、百分比、人数、钱数、资质等级、"唯一/首家/不到X%"。凡不是用户亲自给的，一律进占位清单。详见 `references/fabricated-content-audit.md`。

## 证据的交付形态：给真图，或给能一步截图的链接（2026-10-12 徐总强化）

只写"来源：某某报告"的依据清单是**不合格交付**——用户还得自己去搜、自己去截图。徐总原话：**"你最好直接给出截图，连同文案一起放入压缩文件，实在不行你可以给我链接，让我自己去截图。"**

每条引用 / 画中画叠加点，按优先级必须满足以下之一：

1. ✅ **抓到真实截图**（首选）——放进交付文件夹的 `画中画图片/`，连同文案一起压进 zip
2. ✅ **可直达链接 + 关键词 + 位置**——写成"打开 `<URL>` → Ctrl+F 搜 `关键词` → 第X节/第X段"，让用户一步到位
3. ❌ **禁止**：只写"来源：某某报告 / 某官网"而不给图也不给链接

### 抓图：`scripts/grab_pip_card.py`

```bash
python3 ~/.hermes/skills/content-creation/content-evidence-discipline/scripts/grab_pip_card.py \
  "<URL>" "<输出.jpg>" "<关键词>" [上移像素，默认180]
```

原理：无头 Chromium 打开页面 → 用 DOM 取**最后一个**含关键词的内容元素（避开导航/页脚/隐藏节点）→ `scrollIntoView({block:'center'})` → 上移少量像素 → 1280×780 @2x 截整屏。
比"元素级截图"稳（元素级常只截到一行 60px 高的段落，做不了数据卡），也比"Playwright `get_by_text` 定位+滚轮"稳（`get_by_text` 常先命中导航链接，页面滚不动，截回来只有页头）。

### 抓完必须验图（硬性）

```bash
tesseract <图.jpg> stdout -l chi_sim | head -20
```

OCR 回读，确认真含目标数据；抓到别家广告页、站点导航、空白页一律**弃用重抓，宁缺勿错**。（本机 vision 通道可能指向纯文本模型、读不了图，OCR 是可靠替代。）

**校验没过 ≠ 图废了（2026-10-15 实测，两次真实误判）**：先读一眼 OCR 全文再判，别一失败就弃图重抓。

- **关键词被视口下沿裁掉**：图里其实有那一段的完整表述，但要引的**下一条原文**（如第八条"当场作出行政许可决定"）落在截屏边界之外 → 症状是"命中一半、缺后一句"。
  对策：`shift`（上移像素，默认 180）**调小**，让视口往下走（本次 `shift=300` 裁掉、`shift=120` 命中）。
  **shift 越大画面越靠上、看到的正文越靠前**——这是最容易搞反的一处。
- **OCR 出的是同页相邻条款**：说明页面找对了、定位也在这一带，只需要用 `shift` 微调，**不要换源站重抓**——
  换源常丢掉"官方全文页"这个更强的证据属性（司法部官网全文 > 某局转载 > 媒体报道）。

判据：**缺的是"同页下一条"→ 调 shift；缺的是"整页都不是目标内容"→ 才换源。**

### 失败模式与对策（实测）

| 现象 | 原因 | 对策 |
|---|---|---|
| 输出 0 字节 / 空文件 | 图床防盗链（凤凰等） | 别直下原图，改截**渲染后的页面** |
| 只有页头/导航 | 关键词命中导航，或懒加载未完 | 用抓图器"最后一个内容元素"策略；`domcontentloaded` 后等 4s 再截 |
| `NO_KW_MATCH` / 无正文 | 政府站 JS 壳页（实测 `customs.gov.cn`） | 换财政部/税务总局**正文页**，或权威媒体转载版（新华网原稿） |
| 抓到代办公司广告页 | 搜索排名靠前的是营销页 | OCR 校验发现即弃用，只认官网/权威媒体 |
| 关键词命中、却缺后半句或"下一条原文" | 视口把需要的段落压在截屏边界外 | 调**小** shift 重抓（实测 300→120 命中）；先读 OCR 全文再判，别急着换源 |

### 交付打包（一任务一包，2026-10-12 徐总定）

一个任务的全部产物 → 同名文件夹 → **压成一个 zip**，桌面只留压缩包，禁零散：

```
<任务名>/
├── <文案>.docx  +  <文案>.txt
├── 画中画图片/  画中画_<脚本>_<内容>_<来源>.jpg
└── 画中画来源清单.txt   # 每条：对应脚本/叠加点 → 图文件名 或 链接+关键词+位置
```

打包用单个 Python 脚本做 `folder → zipfile 写入 → shutil.rmtree(folder)`（勿用 shell `rm`，会触发破坏性守卫）；中文名 zipfile 自带 UTF-8 标志，Windows 解压不乱码。
坑：松散 docx 还开在 Word 里时删除报 `PermissionError[Errno13]`（文件被锁）——勿重试，如实报请用户关 Word。

详见 `references/evidence-screenshot-capture.md`（本次实测可用源清单、逐条抓取与 OCR 校验记录）。

## 本地口径查不到时：降级，不硬编（2026-10-15 城市破播实测）

城市破播类内容的红线是"每条必须含一个**可查证的苏州真实事实**"。当选题落在**本地办理口径**上
（"苏州办这个证要几天、要什么材料"）而检索不到苏州/江苏的可引用官方文件时：

- ❌ **不要**把国家层面规定当成苏州口径讲（"苏州现在当场就能批"＝无据断言），也不要拿外省数字充数
  （外地承诺办结时限 ≠ 苏州口径）。
- ✅ **降级成形**：这条改按"行业自然流"写——只讲全国性法规原文 + 通用避坑点；
  苏州只作"我们服务的地域"自然出现（"在苏州做这行的老板"），**全篇不断言任何本地政策/时限/做法**。
- ✅ **交付时显式说明**：讲清为什么没按城市破播写、缺哪份文件；并写进《待核实清单》，
  注明"要城市破播版需先核到苏州/江苏官方口径（文件号+日期）"。

原则：用户要的是可用成稿，但**降级并说清 > 编一条本地政策**。编出来的本地口径一旦被同行或客户核对就是硬伤，
而且它读起来比国家层面法规更像"内部消息"，最难被当场发现。

本次实测：2026-10-15 检索苏州本级人力资源服务许可告知承诺制，未获可引用官方文件；
只核到人社部全国口径（部令第50号第七、八条 + 2022-09 通知）→ 该条即按行业自然流定稿，
把"苏州口径未核实"写进了交付说明与《待核实清单》。

## 用户素材里自带的第一人称事实＝待确认项（2026-10 短视频选题实测）

徐总给的选题/开头里，常夹着一句**关于盈信自己的具体事实**，例如"这是**昨天刚刚取得**的人力资源服务许可证"。
这句话不是"用户提供的原文当素材用"（那句话针对政策原文/客户资料），而是**待确认的事实主张**——
写进文案就是把公司背书押上去了。**不得直接采用，必须先问清主体。**

### 主体三问（涉及自家资质/证照/业绩的素材，动笔前必过）

1. **这张证/这件事是谁的？** 自家办下的 / 帮客户办的 / 根本没有这件事。
   - 自家的 → 可说"我们自己的证"，还能讲"我们自己办过，知道坑在哪"；
   - 帮客户办的 → **必须写成"刚帮客户拿下来"**，以自己名义说"我们已取得"＝虚假宣传风险；
   - 没有 → 这句"刚刚取得"整句不能用，改成不涉及具体主体事实的写法（如"最近有老板问我…"）。
2. **证照类素材怎么拍？** 许可证/执照上有机构全称、编号、地址 → 只拍封皮/局部或打码，
   不得露出客户名称与证号（同时叠加脱敏纪律）。
3. **我们真的在做这项业务吗？** 若盈信只做注册+记账、不代办该资质，文案落点要收回
   "经营范围匹配 + 财税合规"，不要把"代办资质"说成主业——说成主业等于对客承诺了自己交付不了的事。

交付这类选题方案时，把三问连同"需你拍板"一起列在交付消息里（本次即按此交付，用户未反对）。
**别自己替用户假定主体**：假定"是我们的证"再被否，等于一次对外事实违规已成型。

## Pitfalls

- **用户提供的原文 > 检索结果** —— 但**只适用于政策原文/法规文本/客户资料**；用户素材里关于
  **自家公司的主体性事实**（"我们已取得X证""我们有N年经验"）不在此列，属于待确认项，先问再用。
- **监控≠事实**：苏州政策监控推送的是标题+URL（线索），不是已核实的内容；写成文案前必须走核实四步，否则就会踩"低空条例='立法层面'"的次序违规（详细案例见 `references/policy-fact-verification.md`）
- 政务网正文 URL 偶尔返回首页壳（JS 渲染/链接漂移）→ 换 anysearch 找直抓的正文或权威媒体报道，不硬耗
- 政府列表页是 JS 渲染抓不到结构化列表，但**正文单页**通常可抓（requests/web_extract 均可）
- 观点要标"这是看法"，政策解读要标"以官网最新为准"
- 用户提供原文时：用户提供的全文 > 检索结果，直接当素材用，搜索只作补充验证
- **"为了结构好看先编着"不是免责条款**：编造必须配上显式占位标记 + 交付时逐条点名，两条都做到才算合规；悄悄写进正文、看起来像正常内容，即使结构更顺也是幻觉违规
- **AI 自填的"具体事实"默认可疑**：院校/届别/年份/人数/占比/客户数/"N年经验"/"唯一/首家"这类具体事实，凡是 AI 自己写进去的，交付前必须自查一遍或标红反问用户——它们读起来最像真的，也最难被用户当场发现
- **被点名后要查全篇，不只改那一处**（见上文占位纪律的连带必做动作）
- **自己手滑写错 ≠ 待核实**：明知正确答案却写错（如公司所在地"湖北"实为苏州/双城），是笔误 → **当场改正**；把它标成「待核实/待核对」推给用户，等于把确定的错误包装成待定项，用户还得替你审一遍——比直接改更伤信任。占位只留给"真不知道答案"的事实（占位纪律第4条）
- **"给了来源名"≠"给了依据"**：只写"来源：某某报告"而没给截图、也没给可直达链接+关键词，用户仍然要自己搜——这是**不合格交付**（2026-10-12 徐总点名）。清单里每条都要落到"图"或"能一步定位的链接"。
- **抓图要验图**：抓完必 `tesseract <图> stdout -l chi_sim` 回读；搜索排名靠前的常是代办公司广告页，OCR 一看就露馅 → 弃用重抓，宁缺勿错
- **别用元素级/文本定位抓数据卡**：元素级只截到一行，Playwright `get_by_text` 常命中导航导致滚不动 → 用 `scripts/grab_pip_card.py`（DOM 最后一个内容元素 + scrollIntoView 居中 + 截整屏）
