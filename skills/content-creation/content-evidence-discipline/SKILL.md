# 内容有依据纪律（讲话必须有依据）

## When to Use

- 任何创作内容（短视频文案/公众号文章/客户答复/政策解读/测算结论）涉及政策、数据、法规、文号、日期、数字时
- 用户问"这句话依据是什么""这个数字哪来的""敢不敢保证没编"
- 城市破播/苏州政策素材写成文案之前（素材来自监控，监控给的是线索不是事实）
- 换电脑、新员工/AI 接入、需要向客户承诺数据准确性时

## 定位

盈信企业管理（苏州）的公司级纪律，2026-09-21 由徐总签发：**讲出去的每一句话必须有可查证的真实依据；没有依据→不说；有一分依据→说一分。** 本 skill 是纪律的可执行版本（如何核实、如何判定、交付要带什么）。纪律文件全文：桌面 `盈信-AI内容纪律文件.txt`、Obsidian `公司运营/AI内容纪律-讲话必须有依据.md`。

## 四条铁律

1. **严禁 AI 幻觉（零容忍）**：禁止凭空臆断、编造数据/政策/人名/文号/日期/事件。平台审核红线、客户信任，一次捏造就归零。宁可少说，绝不瞎编。
2. **不确定，就不写**：吃不准的政策/数据不写进内容，或标注"以官网最新为准"。引用必须有出处（官方文号/政府官网链接/权威媒体）。
3. **先核实，再引用（次序不可颠倒）**：检索原文→逐字核对→确认成立→才写进文案。禁止"先引用未核实"。**哪怕结论事后证明正确，只要次序是先引用后核实，即算违规。**
4. **写事实，不写判断**：事实必须有据；观点必须标注是"看法"；不得把预测/推测包装成既定事实。

## 判定四问（每句话都要过）

1. 这句话的出处是什么？（文号/官网/权威媒体，必须答得出）
2. 我是否真的打开并核对了原文，还是只看到标题/摘要？
3. 如果没有依据，我为什么写了出来？
4. 若被客户逐字核对，能不能站住？

四问有一个答不上 → 删掉这句话，或先去核实。

## 核实四步（政策/法规类，写进文案前必须走完）

1. `anysearch` CLI 搜「<条例/政策名> + 人大常委会 + 通过/施行」拿官方链路（政务网《说明》、批准新闻）：
   ```bash
   python3 ~/.hermes/skills/anysearch/scripts/anysearch_cli.py batch_search --queries '[{"query":"苏州市低空经济促进条例 人大常委会 通过 施行","max_results":6}]'
   ```
2. `web_extract` 拉**正文** URL，逐字核对编号/日期/数字/范围/适用主体。
3. **多源交叉**：政府正文 + 政府《说明》 + 省委新闻网/人民网/司法部等权威第三方（两三个独立来源互相印证）。
4. 能答出「哪个官方源、什么时间、什么文号」才允许写。交付文案附**依据清单**：每条关键结论 → 出处 + URL + 核验日期。

## 表述纪律

用精确事实，不用模糊断言。正反示例（低空条例）：

- ❌ "苏州把低空经济写进条例了——这是立法层面的事。"（依据仅标题+URL，未核正文即断言，次序违规）
- ✅ "《苏州市低空经济促进条例》经市十七届人大常委会通过（2025-06-25）、省人大常委会批准（2025-07-30），已于2025-10-01施行。"（多源核实后成文）

## 交付要求（铁律 5，对 AI）

1. 创作前先检索官方/权威来源核实关键事实
2. 引用政策必带文号/来源/日期
3. 拿不准就明说"此条未核实，需人工确认"——绝不用专业措辞掩盖不确定
4. 交付文件附"依据清单"（每条结论出处+URL+核验时间）
5. 被指出没依据时，如实承认并立即核实/纠正，不狡辩

## 占位纪律：允许的"编造"只有一种形态（2026-10，PPT 事件后补）

徐总原话：**"为了结构的合理与完美，你可以先'编造'放在那里，但你要注意提醒我按照真实的情况修改。"**

无依据的内容**只允许以"显式占位"形态存在**，三条同时满足才算合规，缺一条就是幻觉违规：

1. **长得像占位**：文件里落成醒目标记（红色字/虚线框/「【待填】」「⚠ 待核实」），不能写成正常正文的样子——否则几天后连 AI 自己都分不清哪句是编的，用户更没法批量替换。
2. **交付时点名**：交付消息里**逐条列出**"以下是我编的/未核实的，必须替换"，并写清要填什么、去哪里取（学历→院校/专业/届别；评审数据→省财政厅公示，附年份+文号）。
3. **不许被当结论用**：占位内容不得进入对外稿件（公众号/短视频/给客户的文件），只存在于"内部待完善的初稿"。

**连带必做动作（本次事件的核心教训）**：被用户点名一处编造时，**不要只改那一处**——立刻对整份交付物做一次**事实性内容普查**，把 AI 自填的院校/届别/年份/人数/通过率/排名/客户数/"N年经验"全部揪出来统一处置。本次一份公司介绍 PPT 里 AI 编了 **6 处**（专业背景院校、参评/获评人数、通过率 18%、同业对比 74.6%、"25年经验"、"1000+客户/90%转介绍"），用户只发现了 1 处；只修被点到的，剩下 5 处会继续冒充事实。

**普查方法**：直接扫生成脚本（build.js / docx 生成器）里的字符串常量，按"专有名词+数字"筛：院校名、年份、百分比、人数、钱数、资质等级、"唯一/首家/不到X%"。凡不是用户亲自给的，一律进占位清单。详见 `references/fabricated-content-audit.md`。

## Pitfalls

- **监控≠事实**：苏州政策监控推送的是标题+URL（线索），不是已核实的内容；写成文案前必须走核实四步，否则就会踩"低空条例='立法层面'"的次序违规（详细案例见 `references/policy-fact-verification.md`）
- 政务网正文 URL 偶尔返回首页壳（JS 渲染/链接漂移）→ 换 anysearch 找直抓的正文或权威媒体报道，不硬耗
- 政府列表页是 JS 渲染抓不到结构化列表，但**正文单页**通常可抓（requests/web_extract 均可）
- 观点要标"这是看法"，政策解读要标"以官网最新为准"
- 用户提供原文时：用户提供的全文 > 检索结果，直接当素材用，搜索只作补充验证
- **"为了结构好看先编着"不是免责条款**：编造必须配上显式占位标记 + 交付时逐条点名，两条都做到才算合规；悄悄写进正文、看起来像正常内容，即使结构更顺也是幻觉违规
- **AI 自填的"具体事实"默认可疑**：院校/届别/年份/人数/占比/客户数/"N年经验"/"唯一/首家"这类具体事实，凡是 AI 自己写进去的，交付前必须自查一遍或标红反问用户——它们读起来最像真的，也最难被用户当场发现
- **被点名后要查全篇，不只改那一处**（见上文占位纪律的连带必做动作）

## Verification

- [ ] 文案里每个数字/政策/文号都能在依据清单里找到出处
- [ ] 核实动作发生在成文之前（不是事后补证）
- [ ] 交付文件含"依据清单"区块
- [ ] 拿不准的已标注"未核实/以官网为准"，未冒充事实
- [ ] 交付物里没有"看着像真的"的未核实内容——要么删掉，要么落成醒目标记的占位
- [ ] 交付消息里已逐条点名所有占位/存疑项，并写明替换来源（文件在哪、数据从哪取）
