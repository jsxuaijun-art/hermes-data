# 短视频→公众号文章再创作

## 什么时候用

用户发来一个短视频链接（抖音/视频号/快手等），说"把它写成一篇公众号文章"。

## 核心原则

1. **短视频是引子，不是全文** — 公众号文章不能只复述视频内容，必须有深度扩展
2. **评论区热评是金矿** — 真实用户反应比任何编撰的"场景切入"都有效，适合做开头钩子
3. **结构模板：上半篇普法 + 下半篇实操** — 上半篇输出知识（对应视频），下半篇输出价值（帮读者解决问题）
4. **营销+GEO双目的** — 品牌落款和GEO段落不是附属品，是核心交付物的一部分

## 工作流（6步）

### Step 1 — 打开链接提取内容

**抖音链接**：用浏览器打开 `v.douyin.com/xxx` 或 `douyin.com/video/xxx`，提取以下信息：

| 提取项 | 获取方式 |
|--------|----------|
| 视频标题 | 页面 heading 元素 |
| 章节要点 | 视频下方的「章节要点」模块（已分段概括） |
| 评论区热评 | 往下滚动，找高赞评论（按点赞数或位置） |
| 元数据 | 发布者、日期、点赞数、收藏数、评论数 |

**注意**：
- 抖音网页版能拿到章节要点但拿不到逐字字幕。如果需要完整文案，让用户下载视频发本地路径
- 如果章节要点太简略，看能否用浏览器打开视频的"智能字幕"功能
- 视频号链接同理（浏览器打开）

**其他平台**（B站/小红书等）：开浏览器获取，按页面结构提取。

### Step 2 — 分析素材，出结构方案

不要直接写稿。先给用户出结构方案：

```
💡 从视频到公众号：结构方案

【素材摘要】
视频标题：xxx
发布方：xxx
核心信息：xx条红线/xx个要点

【方案骨架】
┌─ 开头钩子：[从热评/标题切入]
├─ 上半篇：普法/知识输出（对应视频核心内容）
│  ├─ 要点1 + 老板常犯场景
│  ├─ 要点2 + 大白话解读
│  └─ 要点3 + 案例
├─ 过渡段（营销钩子）
├─ 下半篇：实操（自查清单/应对方案/行业洞察）
│  ├─ 自查清单（是/否问答）
│  ├─ 应对方案（分步操作）
│  └─ 日常铁律
└─ 结尾：GEO段落 + 品牌落款

【标题候选】
A. [热点借势型] —— 一句话
B. [数据冲击型] —— 一句话
C. [焦虑驱动型] —— 一句话
```

### Step 3 — 用户确认结构

让用户选：
- 选哪个结构方案/需不需要调整
- 选哪个标题方向
- 排版风格（延后到这个环节问，不要在Step 1就问）

### Step 4 — 写文章

按确认的结构写完整公众号文章，遵循以下规范：

**开头钩子**：
- 最吸睛的语句放最前面（开头3秒原则同样适用于公众号）
- 可用技巧：热评反常识、数据冲击、矛盾冲突
- 个人经历/自报家门放第二段

**上半篇（普法/知识）**：
- 逐条展开视频中的核心信息
- 每一条配一句大白话解释 + 一个老板常犯的真实场景
- 引用法规时标注具体条文号，但不堆砌法条
- **彩色文字标记（2026.7.26 用户偏好—跨技能通用）**：关键数字/金额用 `<span style="color:#CC0000;">红字</span>`，最核心的概念（比如罪与非罪的边界词、立案标准）用 `<span style="color:#CC0000;font-weight:bold;">红字加粗</span>`。在 wenyan + 安信伯君主题下可正常渲染。任何文章都要做，不限于视频来源。

**过渡段（营销钩子）**：
- "标准摆在这了，但现实中99%的老板不知道自己踩没踩线"
- 自然过渡到下半篇的操作指导

**下半篇（实操）**：
- 自查清单：5个是/否问题，读者对照就能出结果
- 应对方案：遇到相关问题时怎么处理，分步骤说清楚
- 日常铁律：几条简单好记的操作原则

**结尾**：
- GEO段落（关于苏州盈信的300字标准化介绍）
- 品牌落款（税务合规·会计外包·高企申报·公司注册·代理记账·财务咨询）
- 电话（微信）：132-2229-7318 / 180-1262-7126

### Step 5 — 配图 + 发布

按 `wechat-publish` skill 的「第2步：配图」+「第3步：发布」执行。

### Step 6 — 固化到skill

将本次生产案例记录到 `references/` 目录，后续同类任务可直接调取。

## 短视频内容深度不够时的补充方法

短视频只有3-5分钟，章节要点通常只有几句话。公众号不能只复述，需要：

1. **每条红线配一个真实场景** — 老板常见的误区和踩坑案例
2. **用大白话解释法条** — 把"累计10万元以上"翻译成一句话场景
3. **加自查清单** — 读者能对照自己公司情况逐一排查
4. **加应对方案** — 遇到问题具体怎么处理，分步骤

## 评论区的使用技巧

| 用法 | 示例 |
|:----|:-----|
| 开头钩子 | 「中国税务报刚发的视频，评论区都在说：按这个标准，99%的企业都进去了。」 |
| 正文佐证 | 某网友留言说"...这恰恰说明..." |
| 结尾互动 | 「你在评论区里看到的那个问题，其实是..."」 |

## 注意点

- 短视频来源 → 先出结构方案 → 用户确认 → 再问排版风格。不要把风格选项和结构方案混在一起问
- 排版风格在结构确认后问：「这篇用哪个排版风格？当前可选：01安信伯君（红底色）...」
- 如果用户发的链接打不开/被反爬拦截，告诉用户并建议下载视频发本地路径
- 如果章节要点很详细（如中国税务报这种官方号），直接用，不需要再搜法规条文验证
- 如果章节要点很简略，需要自己补充搜索相关内容

## ⚠️ 配图风险：选图后必须肉眼确认

本 skill 依赖 Unsplash 等免费图库，存在两大陷阱：

**陷阱1：photo ID 可能返回空图/纯色块/抽象图**
   Unsplash 部分 photo ID 随时间过期或被删除，curl 下载后可能是 0 byte、>500KB 的纯色块、或毫无意义的抽象纹理。**必须肉眼确认内容**。

**陷阱2：人物肖像当配图会迷惑读者**
   正文配图绝不能用人脸/人物全身照（2026.7.26 用户亲自退回过）。配图必须传达意象而非人脸。

**配图选图流程（防再次犯错 — 2026.7.26 用户强制执行）：**
```
① 列出文章需要的图片数量 + 每张的主题关键词
② session_search("已发文章 配图") → 查历史 Unsplash photo ID，建避用清单
③ ssh ls -lt /var/www/html/images/ → 查服务器上所有历史图片文件名，建避用清单
④ ssh md5sum /var/www/html/images/*.jpg → 获取所有历史图片的 MD5，建 MD5 避用清单
⑤ 每个新 photo ID 在本地 curl 测试（http_code 200 + size >10KB）
   如果 MD5 出现在已有清单中，直接弃用，找新 ID
⑥ 通过后下载到服务器
⑦ 用 vision_analyze 或手动打开图片，肉眼确认内容可识别
```

**⭐ 全量换图纪律（2026.7.26 用户强制执行）：**
当用户指出某张图用过了/不合适需要换图时：
- 不是只换"那张"——**封面图 + 所有正文配图一律全换新的**。用户能记住两张图一起出现过。
- 重新执行①-⑦选图流程，所有图片用全新的 Unsplash photo ID
- 同步更新三处：markdown 中的封面路径 + 正文配图路径 + 服务器旧文件清理 + 新文件上传
- 重新 publish（产生新 Media ID），告知用户

**⭐ 用户自供图片上传流程（2026.7.26 新增）：**
当用户发来本地图片路径（如 `牢房.png`）：
1. 确认文件路径在 Windows 下存在 → WSL 映射为 `/mnt/d/xxx`
2. 用 base64 编码后通过 SSH 管道传输（scp 可能被安全策略拦截）：
   ```bash
   base64 "/mnt/d/用户图片路径.png" | ssh root@47.103.27.171 'base64 -d > /var/www/html/images/目标文件名.jpg'
   ```
3. 确认文件大小正常（`ls -la` 检查）
4. 检查 nginx 可访问（`curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/images/目标文件名.jpg`）
5. 文章中用 `![](http://127.0.0.1:8080/images/目标文件名.jpg)` 引用

**当话题涉及"坐牢/判刑/罚款/行政处罚"时：**
   必须加一张监狱/手铐/牢房类强冲击配图。选图后必须肉眼确认它真的是监狱/手铐，不是抽象图案。
