# 案例库使用说明

## 为什么这个目录最重要

法规和模板，别人也能有。**你自己办过的案子，别人没有。**

这个目录是这个 skill 唯一的、不可复制的资产。它决定了三年后你用这个 skill 时，得到的是"通用税务知识"还是"江敏办过的三百个稽查案子的经验"。

## 怎么用

### 存案例

1. 复制 `_案例模板.md`，重命名为 `YYYY-MM-案由关键词.md`
2. 脱敏后按字段填写
3. 文件名里的"案由关键词"要规范，方便检索。建议用下面的标准案由词：

**标准案由词表**

| 类别 | 案由词 |
|---|---|
| 收入类 | 账外收入、收入未及时确认、视同销售、价外费用、跨期收入 |
| 成本费用类 | 无票支出、虚构成本、业务招待费超标、关联方费用分摊、暂估入账 |
| 发票类 | 虚开发票、接受虚开、三流不一致、发票品名不符、失控发票 |
| 增值税类 | 进项转出、留抵退税、免税与应税划分、简易计税适用 |
| 所得税类 | 研发费用加计、固定资产一次性扣除、关联交易转让定价、股东借款 |
| 个税社保类 | 股东分红、工资薪金、劳务报酬、股权激励、社保基数 |
| 征管程序类 | 追征期、偷税认定、行政处罚裁量、听证、复议、执行 |
| 特殊业务类 | 出口退税、股权转让、重组、注销清算、核定征收 |

### 查案例

需要写文书时，让 AI 先检索这个目录：

> "查一下案例库里有没有 发票类·接受虚开 的案子，参考其中的论证路径"

## 积累节奏建议

- **办完一个案子，当天花 10 分钟存一条**。不要攒，攒了就不会写。
- 填不全没关系，**"可复用要点"和"踩过的坑"两节必填**，其余可以空。
- 一年 20 条，三年 60 条，这个 skill 的价值会超过任何一本税务稽查实务书。

## 质量红线

- 不出现真实企业名、真实税号、真实人名
- 不出现可反推到具体企业的金额、行业细节组合
- 案例只记录**论证方法和程序经验**，不记录任何规避手法

---

## 案例采集触发约定（默认习惯，务必遵守）

**目标**：让"每办一个案子、积累一条经验"成为无脑执行的默认动作，不靠想起来才存。以下情况出现任一，就应存一条案例：

### 什么时候触发
1. **结案或阶段性有结论**（检查阶段有结果、处理/处罚决定下来、复议/听证后）——结案当天存，不攒；
2. **出现"打掉命门"的关键转折**（如无票支出靠"非正常户认定"走通第14条、账外收入靠"稽查举证不能"守住不定偷税）；
3. **定性或金额有实质变化**（偷税→少缴、罚款倍数下调、砍掉大额滞纳金/罚款）；
4. **踩了坑或发现易错点**（算错税率、弄错追征期、文号过时、某条程序途径没走通）；
5. **办案中识别出一个新的"命门变量"**——这是要反哺到 04 案由库的最重要信号。

### 谁来存、存到哪
- **Hermes 优先**（对话中随手存）：按 `cases/_案例模板.md` 结构写，重命名 `YYYY-MM-案由关键词.md`（案由词见 README 上方词表），脱敏后落到 `cases/`。
- **WorkBuddy 补充**：Windows 端碰到的案例按同一模板补进同一目录（源码共享，改一处两边生效）。
- 反哺：识别出的新命门/新案由，同步更新 `references/04-常见案由论证要点.md`，并在 `SKILL.md` 版本记录加一行。

### 填到什么程度
- 「基本信息」「案情摘要」「争议焦点」可以简写，但以下**两节必填**：
  - 「九、可复用要点」——写"下次遇到同类情况我该怎么做"，不只写"这个案子做了什么"；
  - 「十、踩过的坑」——写"这次做错了什么、下次如何避免"。
- 其余字段可空。核心是把"方法论增量"留住，不是记流水账。

### 案例与案由的分工（避免重复/臃肿）
- **案例库（cases/）**＝战例：个案细节、沟通过程、哪份证据/哪句话打动了对方；
- **案由库（04）**＝地图：共性论证路径、标准结构、命门。多个案例验证过的共性结论才上浮到 04，一次性的置于 cases/。

### 数字/文号纪律（与 v2.2 一致）
- 案例里出现的政策文号、刑事门槛、税率比例，若不确定现行版本，标「待核」，交 WorkBuddy 联网核验后，才可作为后续文书的引用依据。案例记录本身可先写，但引用前必须核验。
