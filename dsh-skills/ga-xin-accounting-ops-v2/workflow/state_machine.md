# 状态机：客户研发税务服务的 8 态裁决流程

> 本文件替代 v1 的线性 **S0–S7 查表**。v1 靠"这一步该翻哪份文档"，多条件交叉（高企 + 集成电路 + 亏损 + 委托境外 + 复审年）时无裁决顺序；v2 用**逐状态过闸**：每个状态有入口条件、必需证据、产出、下一态、失败分支。

引擎对应：`engine/rnd_engine.py case <实例.json>` 一次跑完 CALC 及之前所有闸门的机器可判部分；状态机负责机器之外的证据收集、人工复核与对外动作。

---

## 1. 状态总览

```
INTAKE ──► EVIDENCE ──► SETUP ──► COLLECT ──► CALC ──► FILE ──► REVIEW ──► DELIVER
   │           │           │          │          │         │         │          │
   └───────────┴───────────┴──────────┴──────────┴─────────┴─────────┴──────────► HOLD（任一闸门失败）
```

| 状态 | 一句话 | 主要规则 | 引擎字段 |
|---|---|---|---|
| **INTAKE** 准入 | 判断能不能做、走哪条路径 | R001/R020/R002 | `admission` |
| **EVIDENCE** 证据 | 补齐立项、工时、领料、辅助账等证据 | R001（evidence_gate） | `evidence_gaps` |
| **SETUP** 建账 | 按路径建辅助账；高企客户建**两套账** | R019（两套账） | `collection` |
| **COLLECT** 归集 | 六大类费用归集、口径分流、限额调整 | R003–R010、R012 | `limits` / `entrusted` / `collection` |
| **CALC** 测算 | 全链复算 → A107012 逐行 → 加计额 → 风险指标 | R011/R013–R018 | `filing` / `superdeduction` / `indicators` |
| **FILE** 申报 | 预缴三时点 / 汇缴填报、A107012→A107010→A100000 钩稽 | R017 | `filing.prepay` |
| **REVIEW** 复核 | 三级复核、双口径告警、风险处置 | R018 | `risk_hits` / `cross_scope_warnings` |
| **DELIVER** 交付 | 交付物签收、免责边界、归档续作 | —（契约预留） | 实例 JSON 回写 |

**HOLD** 不是失败态，是**显式挂起**：记录 `blocked_by`、整改清单与所需证据，实例 JSON 存档，下轮直接从该状态续作（解决 v1 "无实例、无法跨会话续做"）。

**AUDIT 态（诊断，非服务之旅而是前置于任意态的体检）**：接新客户/复审前/资格存疑时，先跑 `engine/rnd_engine.py audit <审计实例.json>` 做高企账务质量+合规诊断（五维打分 + 整改清单 + 承接结论）。它不插入上面的线性状态，而是**横向闸门**：结果 `≥85` 可直接进 INTAKE 承接；`60–85` 先整改再承接；`<60` 或命中断面清单行业/核定征收 → HOLD 出风险提示函。审计输入契约见 `schema/audit_case.schema.json`，客户材料清单位见 `assets/高企账务质量诊断-材料清单.md`。

## 2. 逐状态契约

### INTAKE — 客户准入与适用性判定

| 项 | 内容 |
|---|---|
| `entry_condition` | 客户提供基本工商信息、行业、上年度收入与研发活动描述 |
| `required_evidence` | 尽调问卷 `assets/客户研发税务尽调问卷.md`、营业执照范围、收入构成表 |
| `裁决顺序` | ① 行业负面清单 → ② 兼营 50% 判定 → ③ 研发活动界定（三口径） → ④ 高企资格有效性 → ⑤ 路径分叉 |
| `outputs` | `path` ∈ {A 高企认定+维持, B 非高企加计扣除, A+B 双路径}；`eligible`；`blocked_by` |
| `next` | `eligible=true` → EVIDENCE |
| `on_fail` | 负面清单命中 / 无真实研发活动 → **不可做（书面说明依据）**；证据不足 → HOLD 待补 |

> **红线**：高企资格不是加计扣除的前提。非高企、科技型中小企业、集成电路/工业母机均可走 B 路径（R011 覆盖）。

### EVIDENCE — 证据链完整性

| 项 | 内容 |
|---|---|
| `entry_condition` | 路径已确定 |
| `required_evidence` | 立项决议、项目计划书、工时表、领料单、设备使用记录、人员名单（≥183 天）、委托/合作合同及科技部门登记、辅助账 |
| `outputs` | `evidence_gaps[]`，每项含缺口名称、影响的规则编号、补证动作 |
| `next` | `evidence_gaps == []` → SETUP |
| `on_fail` | **无辅助账即不得加计**（G08 断言）；不得事后补造台账，只能按 `references/auxiliary_ledger.md` 的合规整改路径补齐 |

> 本状态只做证据完整性判定，不做证据真实性鉴定（属 C 框架，v2 未做，见 `FRAMEWORK.md` §2.4）。

### SETUP — 建账

| 项 | 内容 |
|---|---|
| `entry_condition` | 证据齐备 |
| `outputs` | 辅助账样式选择：2021 简化版 / 2015 版 / 自设样式；高企客户**另建认定专用辅助账**（按近三年分年、按 RD 项目、需中介专项审计） |
| `next` | COLLECT |
| `on_fail` | 高企客户只建一套账 → HOLD，要求补建第二套（R019） |

### COLLECT — 归集与限额

| 项 | 内容 |
|---|---|
| `entry_condition` | 账套就绪 |
| `裁决顺序` | ① 五类费用正列举 → ② 其他相关费用**按全部项目统一计算** 10% 限额（2021年第28号） → ③ 委托境内 ×80% → ④ 委托境外 2/3 限额且 ≤ 境内符合条件 2/3 → ⑤ 资本化四步法与本年摊销 → ⑥ 高企口径独立按 20% 上限另算 |
| `outputs` | `limits.other_related`（含按项目分摊）、`entrusted`、`collection`（双口径并列） |
| `next` | CALC |
| `on_fail` | 把两套口径混算（20% 用进加计、房屋折旧计入加计、装备调试费计入加计）→ 触发 `cross_scope_warnings` 并阻断 CALC |

### CALC — 全链复算

| 项 | 内容 |
|---|---|
| `entry_condition` | 归集结果通过口径检查 |
| `命令` | `python engine/rnd_engine.py case schema/cases/<客户>.json [--as-of YYYY-MM-DD]` |
| `outputs` | `filing.a107012`（第 2/28/34/36/38/40/45/50/51 行）、`superdeduction`、`indicators`、`rate`、`risk_hits`、`trace` |
| `关键钩稽` | **40 = 2 + 36×80% + 38**（38 已是限额后数，**不得重复乘 80%**）；45 = 费用化 + 本年摊销；51 = 45 × 加计比例 |
| `next` | 结果无 `warnings`、无未处置 `risk_hits` → FILE |
| `on_fail` | 两路径复算不一致 / 政策时效无适用规则 → HOLD，人工核政策原文 |

### FILE — 申报

| 项 | 内容 |
|---|---|
| `entry_condition` | 计算链闭合且已复核 |
| `outputs` | 预缴三时点选择（7 月 / 10 月 / 汇缴）、A107012→A107010→A100000 钩稽、A107041 高企优惠行次 |
| `规则` | R017：未在某时点选择享受**不作废**，可在后续时点或汇缴统一享受 |
| `next` | REVIEW |
| `on_fail` | **对外申报是不可逆动作，须用户明确确认**（本技能不代提交） |

### REVIEW — 风险与复核

| 项 | 内容 |
|---|---|
| `entry_condition` | 申报草稿完成 |
| `outputs` | 三级复核签字、量化预警指标处置、双口径差异告知、约谈资料包 7 项 / 核查 9 项 |
| `规则` | R018 阈值命中 → `risk_hits[]` 带 `action` 与 `need_evidence` |
| `next` | DELIVER |
| `on_fail` | 高风险未处置 → HOLD，出风险提示函 |

### DELIVER — 交付与归档

| 项 | 内容 |
|---|---|
| `outputs` | 交付物清单、`assets/留存备查资料清单与签收单.md` 签收、免责边界说明、**实例 JSON 回写归档**（含 `as_of`、所用规则版本、结论与 trace） |
| `next` | 下一年度回到 INTAKE，实例按年度新建但继承客户主数据；高企三年滚动指标从历史实例读取 |
| `on_fail` | 未签收 → 不得关闭项目 |

## 3. 多条件交叉的裁决顺序（v1 缺失的核心）

实例同时命中多个条件时，**按下列固定顺序**逐层裁决，不得跳级、不得按文档顺序随意翻：

```
1. 准入门禁      负面清单 / 兼营50% / 研发活动真实性 / 证据完整性
2. 时点过滤      as_of → 排除失效规则（如 2028 年 44 号 120% 自动回落 100%）
3. 口径分流      加计扣除口径 与 高企认定口径 各自独立计算，禁止交叉污染
4. 归集与限额    五项费用 → 其他10% → 委托80%/2/3 → 资本化摊销
5. 优惠择一      高企15% 与 小微择一（就低），研发加计可叠加；亏损年度结转
6. 风险处置      阈值命中 → 处置动作 → 需补证据
7. 交付签收      复核签字 → 交付物 → 归档
```

同一层内多条规则冲突时按 `priority` 降序，覆盖结果写入 `trace`（记录被覆盖的规则编号与原因），**不静默丢弃**。

> 例：`G05` 黄金案例覆盖「高企 + 集成电路 + 亏损 + 委托境外 + 复审年」五重叠加，6 条断言验证该顺序不产生错误裁决。

## 4. 与年度作业日历的对接

| 时点 | 触发状态 | 说明 |
|---|---|---|
| 年初（1–2 月） | INTAKE / SETUP | 立项决议、建账、确定项目口径 |
| 月度 | COLLECT | 工时、领料、折旧分摊入账 |
| 7 月预缴 | FILE | 上半年研发费可选择享受 |
| 10 月预缴 | FILE | 前三季度研发费 |
| 次年 5 月 31 日前 | CALC → FILE → REVIEW | 汇算清缴、A107012 / A107041 |
| 每年 5 月底前 | REVIEW | 高企年度发展情况报表（累计两年未报取消资格） |
| 资格期满当年 | INTAKE（复审） | 三年指标滚动、重新认定 |

## 5. 状态机的边界

- **机器只做可判部分**：口径、限额、公式、时效、阈值、钩稽。证据真实性、政策原文核验、客户商业判断属人工。
- **不代对外动作**：申报提交、邮件/企微发送、报告对外出具，一律停在 DELIVER 之前等用户确认。
- **HOLD 可续**：实例 JSON 里记录 `current_state` / `blocked_by` / `evidence_gaps`，换会话读文件即可续做，无需重述背景。
