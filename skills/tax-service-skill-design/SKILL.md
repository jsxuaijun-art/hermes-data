# 财税业务服务类 Skill 建设规范

## When to Use

用户说「建/升级/重构财税 skill」「方案要全流程」「政策核验功能」「事前事中事后」「账务诊断」时加载。给盈信（徐总）构建的每一条「业务服务类」财税 skill 都必须满足以下硬性构造，缺一不可。触发词：建财税skill、升级财税skill、财税skill规范、政策时效核验、文号核验、事前事中事后、全流程、高企账务诊断、账务质量体检。

## 1. 政策时效核验——每个财税 skill 的必备功能

每个财税 skill 都必须能**不定时主动核实所引用的政策/法规的有效性**。用错废止或已变更的文号，专业背书瞬间崩塌。核验要落地成**机器子命令**，不是靠人肉翻文档提醒。

可行性落地方案（v2 已验证）：
- **规则/知识数据自带引用元数据**：每条规则带 `authority`（政策文号）+ `effective_from`/`effective_to`（生效期）+ `source`（源书页码）。设计规则结构时就定下这个锚点，核验才能自动化；事后补会漏。
- **verify 子命令**：自动抽取全部引用文号 → 按现行/临期/到期/已废止分类 → 逐号给官方核验信源。
- **官方信源终裁**：税务总局政策法规库 fgk.chinatax.gov.cn、财政部、科技部。fgk 状态标签为准：全文有效 / 已修改 / 全文废止（已修改 ≠ 废止）。
- **到期规则保留沿革勿删除**：`--as-of <历史日期>` 模拟时也要能查到当时口径（如 2028 年加计 120% 回落的模拟）。
- **执行器分工**：skill 的 verify 只负责「抽文号+给信源」，联网终裁交给 cn-regulation-verification（单点）、tax-regulation-monitor（定期巡查），勿重复造轮子。

## 2. 全生命周期——服务类 skill 不能只做单环节

客户服务类流程 skill（高企/注销/账务/合规）要覆盖主体**从普通状态到取得、营运、复审、退场**的完整生命周期，否则只是半拉子。以高企为例：
- 事前：资格预诊断 → 培育（立项/建两套账/IP 布局/硬指标滚动静养 1–3 年）→ 达标认定申报
- 事中：两套辅助账按月归集 → 加计 + 15%/小微择一 → 风险自查
- 事后：年度发展情况报表 → 资格期复审 → 更名/迁移/复核追缴应对 → 退场/转其他优惠

心智：**硬指标是滚动看的（申报前一年/近三年），必须申报前一年就动手建账立项**；临时补只会在复审/复核时翻车。

**定位（徐总明确）**：全流程中以**「事中（账务合规+税务合规）」为最主要工作块**，事前培育/事后年检是支撑面。设计重心放在事中两套辅助账归集、加计+15%择一、风险自查；事前/事后环节给方法即可，不要过度发散。

## 3. 横向 AUDIT 诊断闸门——不是线性状态

诊断（账务质量/合规程度「体检」）不进状态机的线性流，而是**前置于任意阶段的横向闸门**：
- 接新客户：判能不能承接、走哪条路径
- 培育期每年：硬指标是否爬坡达标
- 运营期：归集口径是否仍合规、查风险命中
- 复审前：资格守不守得住

输出一律「多维打分 + 整改清单 + 承接结论」；命中断面清单行业/核定征收 → 高风险禁接/出风险提示函。**客户材料清单做成 assets 交付物**（报表/科目余额表/专用研发账/项目档案/人员/投入/收入/知产/已申报），让客户照单准备，杜绝「不知道要准备什么」。判定阈值复用运营引擎同口径，避免两处口径漂移。

## 4. 口径锚点（财税技能最易翻车处）

高企口径 ≠ 加计扣除口径 ≠ 会计口径，三套并存、各自成体系：
- 其他相关费用：高企 ≤20% vs 加计 ≤10%，两套上限各卡各的（金额按限额公式算，不可混用）
- 委托研发 80%：加计境外另有「境内研发费 2/3」限制，高企无 2/3
- 房屋折旧/租赁：高企可计、加计不可计
- 两套辅助账不能顶替：加计 2021 简化版 ≠ 高企认定专用账（表 7-8），复审时专项审计不认
