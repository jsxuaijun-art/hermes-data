# 反不正当竞争与商誉保护诉讼研判

处理"客户被同业在网上抹黑"这一类案件：别人在官网/短视频/自媒体上发"测评""对比""排行榜"
把客户排末尾、编造投诉率/合规率/成立年份等数据，客户问**能不能告赢、赔多少、公证费谁出**。
也用于**起草或复核**此类起诉状/代理词。

范围界定：本 skill 管**经营者之间**的商誉诋毁（反不正当竞争法第12条商业诋毁、
第9条虚假宣传）及其诉讼研判；不管纯自然人名誉权纠纷，也不管税案/合同纠纷。

## When to Use

- 用户拿来一份"某机构被同行发测评文章贬损"的起诉状/证据，问**赢的概率**
- 问"**公证费/律师费能不能让被告承担**"
- 需要检索**商业诋毁/虚假宣传的类案判例**（尤其"没点名但能被认出来"的情形）
- 需要判断某内容属"正当商业评论"还是"商业诋毁"

## Prerequisites

- 起诉状、证据材料、证据保全路径等源文件（先 `read_file` 逐份读完再下结论）
- 被告主体信息（**法定代表人真实姓名、统一社会信用代码**）——查"国家企业信用信息公示系统"
- 网络检索优先用 `anysearch`（见 `chinese-legal-research` skill）；`web_extract` 对
  cnipa.gov.cn / cclp.sjtu.edu.cn / ipc.court.gov.cn 均可用

## Quick Reference

**第一步永远是核法条版本**（最容易翻车的地方）：
2025-06-27 修订、**2025-10-15 施行**的新《反不正当竞争法》把条文**全部重编号**：

| 主张 | 旧编号(2019) | **新编号(2025)** |
|---|---|---|
| 虚假宣传 | 第8条 | **第9条** |
| 商业诋毁 | 第11条 | **第12条** |
| 民事赔偿 + 合理开支 | 第17条 | **第22条** |
| 行政责任（罚则） | 第23条 | **第28条**（10万–100万；情节严重 100万–500万） |

→ 行为发生在 2025-10-15 之后，**必须用新编号**；客户手上现成的起诉状十有八九引的是旧编号，
**主动指出并要求更正**——这是本类任务里交付物价值最高的一条。

## Procedure

1. **读完源文件**（起诉状 + 策略预案 + 证据保全指引），不要只读标题就开始给概率。
2. **核法条版本**：按上表把每处引用换成新编号；顺手核对新第22条法定赔偿上限的适用范围
   （字面只覆盖第7条混淆、第10条商业秘密），需要时核实现行司法解释。
3. **检索类案**：最高法**年度反不正当竞争典型案例**是首选（带案号、有背书、可 extract）。
   渠道与"测评类诋毁"三件关键案例见 references 第三节。其次用 `anysearch` 抓律所/知产媒体解读。
4. **逐要件比对**：主体+竞争关系 / 编造传播虚假或误导性信息 / 特定指向 / 已经或可能损害。
   每条写清"对应事实 + 赢面 + 剩余风险"，不要笼统写"证据充分"。
5. **预判被告抗辩**：主战场永远是"**我没点名**"和"**AI生成/第三方生成我们只是平台**"两招——都有判例堵死。
6. **拆开给四个概率/区间**（见 references 第九节）：侵权认定概率、判赔金额区间、
   各项开支支持概率、程序风险。**不要只给一个笼统数字。**
7. **单列"必须先改/先核的东西"**：法条序号、被告法定代表人真实姓名、关联被告的法人地位与混同证据、
   商号唯一性 + 主营开票记录。
8. **管辖与共同被告**：地域管辖可择“**原告住所地＝侵权结果发生地**”（网络商业诋毁，最高法网络人身权解释＋生效判例）在原告地基层立案，备退守被告住所地；标的额 <200 万归基层、≥200 万归中院知产庭；预判被告提管辖异议，立案前电话确认收案口径。共同被告/连带的杀手锏 =“国家企业信用信息公示系统**股权穿透**”：母→100%→中间层→100%→子 = 间接全资孙公司，**务必写“间接全资子公司（孙公司）”，勿仅称“母子公司”**（对方会以非直接控股抗辩）；股权穿透＋同址（同园区同楼层）＋官网“多品牌矩阵”自述三者互证“一套班子多块牌子”。详见 `references/jurisdiction-and-co-defendant.md`。

9. **交付**：.docx 落到案件材料所在目录（本用户惯例 `D:\OneDrive\Desktop\名誉侵权（商业诋毁）\`），
   终端同步“先给结论两个数 + 理由 + 风险 + 路线图”。

10. **改稿阶段**（研判交付后，用户几乎总会紧接着说"按你上面列的风险点，重新生成起诉状 / 诉讼策略预案"）：
   ① **逐字段审计原稿的占位符与可疑值**（法定代表人姓名、统一社会信用代码、住所地、金额、
   案号/时间），区分"已核实"与"占位/AI 生成"；② 新稿**另存为 `_修订稿v3` 等新文件名，不覆盖原稿**，
   落同目录；③ 未定项写成 `__________` 并**同行加 `⚠` 说明核实渠道**（如"必须上国家企业信用信息公示
   系统核实后填写"）；④ 成品**回读核对**（`read_file` 读 .docx 全文，含抬头/具状人/落款）；
   ⑤ 终端末尾单列"**提交法院前你必须亲手补的 N 处**"清单；⑥ 交付前跑
   `scripts/check_doc_citations.py`。骨架见 `templates/民事起诉状-商业诋毁框架.md`。

## Pitfalls

- ❌ **别沿用旧法条文序号**。头号错误：2025-10-15 后行为引 2019 编号 = 说理不严谨、易被挑程序瑕疵。
- ❌ **别把"没指名道姓"当成不侵权的理由**（那是被告的逻辑）。最高法典型案例明确：遮盖标识但可识别的
  仍构成商业诋毁；且"故意指而不名"本身可作**主观恶意**论据。
- ❌ **别给单一胜诉数字**。用户要的是可决策的分解：认定概率 / 赔额区间 / 开支支持率 / 程序风险。
- ❌ **别漏竞合风险**：同一行为同时落入虚假宣传（第9条）与商业诋毁（第12条）时，法院可能以
  "重复评价"为由不予双重认定——应以商业诋毁为主案由、金额只主张一次。
- ❌ **别忘程序硬伤**：法定代表人是占位符 = 无法送达甚至不予立案；关联被告非独立法人或混同证据不足
  = 连带责任落空（但不影响对主管主体的认定）。概率评估里必须单列。
- ⚠️ **公证费/律师费主张必须有票据**：无实际支付凭据的取证费法院不予支持（有反面判例）。
- ❌ **⭐ 别把原稿里的脱敏/占位值原样拷进新稿**（本类改稿任务最易翻车的实操错误）：客户原稿的
  当事人字段常是脱敏占位（如原告法定代表人写成 `TT`）或 AI 生成的假名（如被告写成"赵帅甲"）。
  改稿时照搬 = 把上一个错复制成两个错。**生成后必须 `read_file` 回读成品 .docx 逐字段核对**
  （只回读你新写的内容不够——抬头、具状人、落款、金额、证据清单条数全要看），未核实的一律
  写成 `__________ ⚠ 必须查"国家企业信用信息公示系统"后填写`。
- ❌ **别只写占位符不写提示**：占位符必须与"待核实"同时出现、给出核实渠道；只写 `__________`
  用户会直接提交。
- ❌ **别把股权关系笼统写成“母子公司”**：经中间层 100%→100% 控股的是“间接全资子公司（孙公司）”，写准了才封住“非直接控股、无关联”的抗辩；股权穿透截图须含中间层公司并单独列入证据清单。
- ❌ **别把用户的现场改稿当最终稿直接采信**：用户会自己在 v3 上手改（填股权链条、改管辖、删增证据），改稿常带新硬伤——本案例实证：具状日期月日颠倒（2026年12月13日应为10月13日）、单位名错字（“国家税务总局花苏州市税务局”多一个“花”字）、占位符残留（法定代表人仍 TT/TT甲）、与正文矛盾的可删括注（“如撤回对被告二起诉则不需”在股权坐实后必须删）。用户改完后要**逐字段回读 + 单独产出一份《建议修改点清单.docx》**逐条点名，并据此同步更新策略预案；清单落同目录。
- ⚠️ 用 python-docx 生成本类文书时：**循环变量名不要与表格 cells 赋值变量同名**
  （`for a,b,c in rows:` 里若写 `c = table.add_row().cells` → `TypeError: 'in <string>'
  requires string as left operand, not _Cell`），脚本先 `write_file` 到 `/tmp/*.py` 再执行。
- ⚠️ 交付物必须带免责：本研判非代理意见，**法条序号与主体信息请在正式起诉前由执业律师最终确认**。

## Verification

- 文书里搜一遍"第十一条""第八条""第十七条"——若出现在反法语境，基本就是漏改的旧编号。
- 改稿后跑 `scripts/check_doc_citations.py <新稿.docx>` 自动扫旧编号与占位符；
  再 `read_file` 回读核对抬头、具状人、落款、金额、证据清单条数。
- 每个结论都能指到来源：法条（现行文本）或最高法典型案例（案例名 + 法院 + 案号）。
- 概率结论是**区间 + 依据**，不是裸数字。
- 交付前确认 .docx 已生成并给出绝对路径。
